# 夢の思い出を個人のGoogle Driveに保存する

Google Apps Scriptを所有者として実行し、投稿されたJPEGをマイドライブの「TDRoute 夢の思い出」に保存します。GoogleアカウントでTDRouteにログインすると、自分用のアルバムと友達と共有するアルバムを作り、写真をしおりの体験に結び付けられます。Driveのフォルダは「制限付き」のまま使用してください。画像を表示するときもアプリで参加資格を確認します。

## 設定

1. 写真を保存する個人のGoogleアカウントで [Apps Script](https://script.google.com/) に新しい独立したプロジェクトを作成します。Firebaseの管理アカウントとは別のアカウントを使えます。`Code.gs` と `Jpeg.gs` をそれぞれ同名で登録します。
2. プロジェクト設定でマニフェストの表示を有効にして、`appsscript.json` をこのディレクトリの内容に置き換えます。Driveの高度なサービス v3を利用します。標準のGoogle Cloudプロジェクトと関連付けた場合は、そのプロジェクトでもDrive APIを有効にします。
3. 「デプロイ」から新しいウェブアプリを作成します。実行ユーザーは「自分」、アクセスできるユーザーは「全員」です。TDRouteからの通信にはFirebase IDトークンが必要です。写真の保存先となるGoogleアカウントでDrive連携を許可してください。
4. 発行された `/exec` URLをTDRouteの配信用の接続先として設定します。全利用者に配布される接続先は担当者が管理します。利用者が任意の接続先を入力してログイントークンを送ることはできません。公開前にGitHub Pagesから、投稿・表示・削除、招待されていない利用者の拒否を確認します。
5. プログラムを更新するときは「デプロイを管理」から同じデプロイを選び、新しいバージョンを指定します。プロジェクトを作り直すと、既存のアルバムの記録を引き継げません。

## アルバムの種類と招待

「自分だけの思い出」には、自分だけで見る写真をまとめます。「みんなとの思い出」では、作成者がGoogleアカウントを指定して友達を招待できます。写真の共有は投稿者が1枚ごとに選びます。旧版で作ったアルバムは「みんなとの思い出」に入り、以前の管理者が作成者になります。

作成者は「夢の思い出」で対象の共有アルバムを選び、「Googleアカウントで友達とアルバムをシェア」に相手のGoogleアカウントのメインのメールアドレスを入力して「招待」を押します。選択中のアルバムの招待先を一覧で確認でき、各アドレスの横から招待を取り消せます。招待先のアドレスを見られるのは作成者だけです。参加者はアルバム内の呼び名でお互いを確認できます。作成者は招待するときに相手の最初の呼び名を設定でき、各自が後から自分の呼び名を変更できます。未設定の呼び名には「作成者」「メンバー1」などを表示します。Googleのアカウント名は使いません。

友達にはTDRouteのURLを知らせてください。招待メールの自動送信はありません。同じGoogleアカウントでTDRouteにログインすると「夢の思い出」にアルバムが表示されます。学校や会社のGoogle Workspaceのアドレスも使えます。メールの転送先や別名で招待した場合は、ログインに使うメインのアドレスで招待し直してください。組織が外部アプリへのログインを制限している場合は、その管理者に確認してください。

旧版では招待先の照合値だけを記録していました。以前の招待はそのまま有効です。招待された本人がそのアルバムを開くか、作成者が同じアドレスを再び入力して招待すると、次の更新で一覧にアドレスが表示されます。

## 保存と権限

`drive.file` 権限で、このアプリが作成したフォルダと画像を扱います。サーバーの資格情報はApps Scriptが管理します。Firebaseの接続先と旧版のアルバム作成者に使う利用者ID照合値はTDRoute本体と合わせます。別のFirebaseプロジェクトに導入するときはプロジェクトID・公開ウェブAPIキー・管理者照合値を設定してください。

写真を投稿すると `TDRoute 夢の思い出/YYYY/MM/DD/利用者IDの照合値/アルバム名/写真ID.jpg` が自動で作られます。年月日は写真を結び付けたしおりの来園日です。投稿者を表すフォルダ名にはFirebase利用者IDから計算した照合値を使います。同じ来園日・投稿者・アルバムの写真は同じフォルダに入ります。同名の別アルバムにはIDを添えます。アルバム名の区切り文字は全角に置き換えます。既存の写真は元の場所から引き続き表示できます。

アルバムに参加すると写真を投稿できます。公開範囲の初期値は「自分だけ」です。アプリでは投稿時と同じFirebase利用者IDでログインした参加者にだけその写真と体験名を表示します。写真の投稿者が「アルバムのメンバー」に変更すると、他の参加者も見られます。公開範囲が記録されていない写真は「自分だけ」として扱います。

投稿者は自分の写真をアプリから削除できます。共有アルバムの作成者は、メンバーに公開された写真も個別に削除できます。「自分だけ」の写真をアプリから開けるのは投稿者だけです。

共有アルバムを一覧から外すと、その操作をした人の一覧からだけ消えます。「再表示」で写真・参加資格・作成者の管理権限を元どおり使えます。他の参加者は引き続き共有写真を見られます。特定の人の参加資格を取り消したいときは、作成者がその人の招待を取り消します。自分用のアルバムを削除すると、本人のアプリからアルバムと写真の記録が消えます。どちらの操作でも保存済みの画像とフォルダはDriveに残ります。共有の解除後は新しい写真取得リクエストを拒否します。端末へ保存した画像は各利用者が管理します。

アルバム名・作成者の利用者IDの照合値・アルバム内の呼び名・招待先のメールアドレスとその照合値・投稿者の利用者IDの照合値・写真ごとの公開範囲・画像と体験の対応は専用スクリプトのプロパティに保存します。画像本体に含めるのはリサイズされたJPEGの表示データです。投稿時に位置情報などの付加情報を除きます。ファイルIDや投稿者の名前を表示するDriveリンクは配信しません。実際の旅程・個人の写真・認証トークンはGitに保存しません。

## アルバムの利用枠

アルバムの新規作成は、作成者ごとに表示中のアルバム12冊、一覧から外したものを含めて24冊までです。招待されたアルバムは作成数に含みません。アルバムごとに招待12人、写真40枚までです。写真は長辺2,048px・1,000,000バイトまでです。

画像は削除後もDriveに保管するため、新しい画像の保存は日本時間の1日あたり1人40枚・全体300枚が上限です。アプリから削除しても当日の使用枚数は減りません。同じ保存の再試行は、その日に同じDriveファイルの枠を再び消費しません。アルバム記録はスクリプト全体で120冊までとし、Script Propertiesの上限に近づいた場合は新規作成・新規投稿を停止します。これらの利用枠とDriveの契約容量は個別に管理します。
