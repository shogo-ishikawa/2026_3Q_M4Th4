# 歌声のゆらぎを調べる操作マニュアル

Vocal Fluctuation Labは、Webで音と波の基礎を学び、Colabで歌声の音量が時間とともにどう揺れるかを調べる教材です。Webは「音と波 → スペクトル → 1/fゆらぎ」の順に進みます。自分の音源を解析するときは、次の手順でColabを開いてください。

## Webで音と波を学ぶ

[公開ページ](https://shogo-ishikawa.github.io/2026_3Q_M4Th4/vocal-fluctuation-lab/)は、初めて音声解析に触れる方向けの学習ページです。Pythonを準備せずに使えます。

1. 「音と波」で振れ幅と周波数のスライダーを動かします。「この波を聴く」は3秒で止まり、停止ボタンでも止められます。
2. 「スペクトル」で440 Hzの成分を増減し、波形と成分のパワーを比べます。
3. 「1/fゆらぎ」で白色・ピンク・褐色を切り替えます。音量の時間変化と、その変化の速さを表すスペクトルを見比べます。
4. 表示された傾き、使用帯域、R²を確認します。周波数と周期の表や、Colabの結果を読む説明も利用できます。
5. 自分の音源を調べるときは「Colabで自分の音源を解析」へ進みます。保存済みの歌声WAVを使う手順も、ページ内の折り畳みから確認できます。

登録曲の一覧は「DB一覧」から確認できます。「自分の歌声で試す」では、録音してからColabへ進む手順を読めます。

Webの図は説明用の合成例です。音源のアップロード、歌声の分離、実際の解析と比較DBの操作はColabで行います。

## 1 Colabの準備

1. [Colab v1.7.1用Notebook](https://colab.research.google.com/github/shogo-ishikawa/2026_3Q_M4Th4/blob/main/projects/vocal-fluctuation-lab/notebooks/vocal_fluctuation_lab_v1.7.1.ipynb)を開きます。
2. Googleアカウントへのログインが必要な場合はログインします。
3. 歌声分離にGPUを使う場合は、Colabの「ランタイム」からランタイムのタイプを変更し、利用できるGPUを選びます。利用できないときはCPUでも処理できます。
4. Notebookの最初の準備セルを実行します。ライブラリの取得には時間がかかる場合があります。処理が終わるまで待ちます。
5. 次の「解析画面を開く」セルを実行します。
6. 操作画面の上部でv1.7.1の表示を確認します。「曲全体を解析」「秒数をリセット（0〜90秒）」「解析モード」「無音の調整」を使えます。最大10分まで処理できます。

ColabのランタイムやGPUの提供には利用条件と制限があります。画面上で選べる環境を使ってください。設定や依存関係の詳しい説明はNotebookにも記載しています。

## 2 音源を指定

### ファイルから始める

1. 「ファイルをアップロード」を選びます。
2. 「音源を選ぶ」を押し、その後に出る選択欄からMP3、WAV、M4A、FLACなどを1つ選びます。Colabでは転送が完了するまで待ちます。
3. 「今回の音源」にファイル名と大きさが表示されたことを確認します。ここに表示された1ファイルだけを解析します。選び直すと以前の音源を置き換えます。
4. 歌声だけのファイルであれば「歌声だけの音源です（分離を省略）」にチェックを入れます。伴奏入りの音源ではチェックを外します。

ファイルはColabの実行環境へアップロードします。このGitHubリポジトリやPagesの公開サイトへ登録する操作ではありません。自分の録音や、利用できることを確認した音源を使ってください。

1ファイルの上限は512 MiBです。Colabでは大きなWAVを通常のウィジェットに載せず、Colab標準の転送経路を使います。解析できる時間は引き続き最大10分です。選択を取り消した場合、取り込みに失敗した場合、指定したパスが使えなかった場合は、以前の音源と結果の選択を解除します。新しく名前が表示されてから解析してください。

### 選択したファイルが反映されない場合

1. Notebookで「音源を取り込む（選択が反映されない場合）」まで進みます。
2. そのセルの実行用チェックをオンにして、セルの▶を押します。
3. **このセルの実行後に出る選択欄**から音源を1つ選びます。
4. 転送の完了を待ち、解析画面の「今回の音源」にファイル名と大きさが表示されたことを確認します。
5. 解析画面へ戻り、区間と解析モードを選んで「解析を始める」を押します。

この補助セルは、チェックがオフのままなら音源の取り込みを始めません。通常は解析画面の「音源を選ぶ」から進めます。

### Colab内にある音源を指定する

Colabの左側のファイル欄へ既にアップロードした場合や、接続済みのGoogle Driveに音源がある場合は、解析画面のファイル指定欄を開きます。実際のパスを入力し、「このファイルを使う」を押します。例えば `/content/vocals.wav` は、そこへ配置した音源を使う場合の例です。自分の音源のパスに置き換えてください。

この操作では指定したファイルを読み込みます。元のファイルは書き換えません。音源を指定した後は、「今回の音源」の表示を確認します。

CDから取り込んだWAVやFLAC、ダウンロード購入したAAC（M4A・MP4）も使えます。購入データがZIPの場合は展開して、音声ファイルを1つ選んでください。音声ファイルとして取り出せる音源を使います。

### YouTubeから始める

1. 「YouTube URL」を選びます。
2. 動画を一つだけ指定するURLを入力します。再生リストやライブ配信は対象にしません。
3. 開始・終了の秒数を入力するか「曲全体を解析」を選び、解析します。

公開状態、地域制限、YouTube側の取得制限などで取得できない場合があります。取得に失敗したら、利用できるファイルをアップロードしてください。この機能は取得制限を回避する仕組みではありません。

## 3 開始と終了を秒で指定

「開始（秒）」は音源の先頭を0秒とした開始位置です。「終了（秒）」は解析を終える位置で、解析する長さそのものではありません。

「曲全体を解析」にチェックを入れると、秒数の欄を使わず、音源の先頭から最後までを解析します。音源の長さをあらかじめ調べて入力する必要はありません。「秒数をリセット（0〜90秒）」を押すと、曲全体の選択を外し、開始0秒・終了90秒へ戻します。

| 調べたい区間 | 開始（秒） | 終了（秒） | 長さ |
| --- | ---: | ---: | ---: |
| 先頭から90秒 | 0 | 90 | 90秒 |
| 40秒から2分10秒まで | 40 | 130 | 90秒 |
| 1分から3分まで | 60 | 180 | 120秒 |
| 先頭から5分 | 0 | 300 | 300秒 |

曲全体・手動の区間指定とも、処理する長さは10〜600秒（最大10分）です。長すぎる音源では、まず一部の区間を指定します。無音の調整後に残った歌声が60秒未満なら、ゆっくりした変動を判断する材料が少ないため、1/fに近いかどうかの判定を保留します。手動の区間指定では、元の音源が終了位置まであることも確認してください。

初めは歌声が続いている90秒程度でも試せます。その後、曲全体と、同じ長さで切り出した複数の区間を比べてみましょう。曲全体にはイントロ、サビ、間奏といった構成の違いも入るため、全体の長さだけで測定の良さは決まりません。

### 解析モードを選ぶ

| モード | 使う場面 | 帯域と窓の決め方 |
| --- | --- | --- |
| 自動 | 初めての解析、曲全体の探索 | 無音調整後の長さに合わせ、低周波側とWelch法の窓を調整する |
| 固定 | 比較DBの作成と問い合わせ | 共通の0.2〜20 Hzを使い、Welch法の窓を最大20秒にそろえる |

どちらのモードも、20 Hzまでの結果と、同じ下限から5 Hzまでの結果を並べます。データが短い場合は、無理に遅い変動まで調べず、実際に使える下限を引き上げます。使用した帯域、対応する変動の周期、窓の長さを結果で確認してください。

周波数の下限は、音源の長さだけでなく、スペクトルを求める一区間の長さにも制約されます。上限20 Hzはこの実装で扱う範囲であり、1/fの普遍的な境界ではありません。帯域を広げて傾きが変わったことも、測定の結果として読みます。

## 4 歌声を取り出して解析

1. 「解析モード」を選びます。最初は自動、比較DBを使う場合は固定にします。「処理装置」は通常「自動（GPUを優先）」を選びます。
2. 「解析を始める」を押します。
3. 表示される処理の進み具合を見て、完了まで待ちます。初回はAIモデルも取得します。
4. 「元の区間」「抽出した歌声（無音調整前）」「解析に使った歌声（無音調整後）」を再生します。

歌声抽出はDemucsによる推定です。伴奏が残る場合や、歌声が欠ける場合があります。抽出結果を耳でも確認してください。伴奏が強く残っていれば、結果は歌声だけの変動とは解釈しにくくなります。

### コーラスや重ね録りがある場合

主旋律、コーラス、ハモリ、別テイクの重ね録りは、まとめて歌声に含まれる場合があります。現在の分離処理は、それぞれの声を別のトラックへ分けるものではありません。リバーブやディレイも音量変動へ影響します。結果は**完成音源に含まれるボーカル全体のゆらぎ**として読みます。

同じ録音を同時刻に重ねて音量だけを変えた理想的な場合は、スペクトルの高さが変わっても傾きは変わりません。一方、別テイクやハモリは強弱やタイミングを変えるため、1/fに近づく場合も遠ざかる場合もあります。主旋律の特徴に注目する場合は、コーラスの少ない区間を複数比べてください。コーラスの影響を厳密に分けるには、同じ区間の主旋律だけの音源が必要です。

GPUのメモリ不足で失敗した場合は「CPU」を選んで再実行できます。CPUでは処理時間が長くなる場合があります。GPUを明示的に使いたい場合だけ「GPU（CUDA）」を選びます。

### 無音を調整する

「無音の調整」を開くと、歌声を抽出した後の無音処理を変更できます。

| 操作 | 標準の値・動作 |
| --- | --- |
| 前後の無音を自動で除く | オン。歌声の前後の静かな部分を除く |
| 途中の無音も除く（時間を短縮） | オフ。途中の休符や間奏をそのまま残す |
| 無音のしきい値 [dB] | −40dB。抽出した歌声の最大RMSに対する相対値 |
| 除く無音の長さ [秒] | 0.5秒。途中の無音を除く場合の最短の長さ |

−40dBは、RMS振幅で最大値の約1%に当たります。無音とみなす境界の前後には0.05秒の余白を残します。静かな歌声まで落としてしまわないか、「抽出した歌声（無音調整前）」と「解析に使った歌声（無音調整後）」を聴き比べてください。処理前後の長さと、除いた秒数も表示します。

途中の無音を除くと、離れていた歌声がつながり、時間軸が短くなります。この結果は**加工後の歌声の参考値**です。元の曲のリズムや時間的な相関をそのまま調べた結果ではありません。必要に応じてオン・オフを切り替えて再解析し、変化を確かめます。

## 5 結果を読む

### 音量の時間変化

最初のグラフはRMSという音量の目安を時間順に並べたものです。山が高いほど、その短い時間の音の振幅が大きいことを表します。音の高さそのものを描いた図ではありません。

開始・終了の入力は元の音源の先頭を基準にします。グラフの横軸は、無音の調整後に解析へ使った歌声の経過時間です。途中の無音を除いた場合は「時間短縮後の経過時間」と表示し、元の曲の時刻とは区別します。結果JSONには、選んだ区間の先頭を0秒とした位置と、加工後に残した位置との対応も記録します。元音源での位置は、この区間内の位置に指定した開始秒を足した時刻です。

### ゆらぎのパワースペクトル

ゆっくりした揺れと速い揺れがどれくらい含まれるかを表します。例えば0.2 Hzは約5秒、5 Hzは約0.2秒、20 Hzは約0.05秒の周期の変化に対応します。声そのものの「100 Hzの音」といった高さとは別の周波数です。

両対数の図で、横軸の周波数を10倍にしたときパワーが約10分の1になる傾きが、1/fに対応する−1です。ただし、一本の直線を引けただけでは十分ではありません。

| 表示 | 確認すること |
| --- | --- |
| 傾き β | −1からどのくらい離れているか |
| R² | 対数の点が直線にどのくらい近いか |
| 解析した周波数範囲と周期 | どの速さの揺れを比べたか |
| 帯域ごとの比較 | 上限を5 Hzから20 Hzへ広げても、傾きや当てはまりが維持されるか |
| 区間ごとの傾き | 解析した歌声を四等分しても、結果が大きく変わらないか |
| 判定理由 | 長さ、無音の割合、データ点の不足などがないか |


### β：ゆらぎの傾きを読む

β（ベータ）は、音量のゆらぎのスペクトルを両対数のグラフにしたときの直線の傾きです。関係は `P(f) ∝ f^β` と表せます。ここでのfは、音量が変わる速さです。声の高さや音量そのものを表す数値ではありません。

| βの目安 | 周波数を10倍にするとパワーは | 読み方 |
| --- | --- | --- |
| 0 | ほぼ同じ | 調べた範囲では、変化の速さによる偏りが小さい |
| −1 | 約10分の1 | 1/fに対応する傾き |
| −2 | 約100分の1 | −1より急な傾きで、相対的にゆっくりした変動へパワーが偏る |

βがより負になるほど、速い変動に対して遅い変動の割合が大きくなります。**1/fへの近さは−1との差で読みます。** 例えば−0.9と−1.1は、どちらも−1から0.1だけ離れているため同じ近さです。値が大きいほど、あるいは傾きが急なほど良いという点数ではありません。

### R²：一本の直線で表しやすいかを読む

R²は、対数周波数ごとにまとめたPSDの点が、当てはめた直線にどれくらい沿っているかを示します。この画面では0〜1の値を表示し、1に近いほど直線に沿い、低いほど一本の直線でまとめる説明が弱くなります。曲線になっている場合や、周波数帯ごとに傾きが違う場合も、R²が低くなる理由になります。

**R²が高いことと、βが−1に近いことを一緒に確認します。** R²は「1/fである確率」ではなく、R²が0.95でも「95%の確率で1/f」という意味にはなりません。歌唱力や声の魅力を表す数値でもありません。

βが0付近の平らな例では、小さなばらつきにR²が左右されます。録音の良し悪しを採点する値としては使いません。

次の数値は読み方を説明するための仮の例です。曲やアーティストの測定値ではありません。

| β | R² | 読み方 |
| --- | --- | --- |
| −1.05 | 0.95 | 傾きが−1に近く、直線にも沿う。長さや区間ごとの安定性も満たせば、その帯域で1/fに近い傾向と読める |
| −1.02 | 0.40 | 傾きの数値は−1に近いが、直線への当てはまりが弱い。このツールでは判定保留 |
| −1.80 | 0.96 | 直線にはよく沿うが、傾きは−1から離れている。直線的なスペクトルでも1/fに近いとは言えない |

この教材では、**−1との差が0.3以内、かつR²が0.75以上**を「1/fに近い傾向」の探索用基準にしています。これは普遍的な証明の基準ではありません。無音調整後に60秒以上あること、十分な変動と周波数範囲があること、時間を分けても傾きが大きく変わらないことなども必要です。画面の丸めた値だけで境界を判断せず、実際の判定理由を確認してください。

区間による変動は、解析に使った歌声を重ならない4区間へ分け、それぞれの傾きを比べたものです。長い音源では各区間の中で複数の窓を平均できるため、推定のばらつきを減らせます。それでも、イントロとサビなどの構成の違いは残ります。長ければ常に良いという意味ではありません。

表示する差は、時間を選ぶことによる変動の目安で、信頼区間ではありません。曲全体の結果に加え、同じ長さで切り出した複数の区間でも確かめてください。

### 三つの表示

- **指定条件で1/fに近い**：このツールの探索用基準を満たしました。別の区間でも確かめます。
- **1/fに近いとは言えない**：必要なデータがあり、区間による変動も小さいものの、傾きが−1の近くにはありません。
- **判定保留**：短い、ほぼ無音、直線への近似が弱い、区間で結果が大きく変わるなどの理由があります。

帯域によって結果が変わる場合は、その違いも残します。最も−1に近い帯域だけを選んで曲全体の性質としないでください。「○〜○ Hzでは1/fに近い傾向」と範囲を添えて説明します。

この評価は歌唱力、声の魅力、健康への効果を表しません。解析の基準は [方法の説明](method.md)に明記しています。

## 6 結果を保存

「結果ZIPを保存」で、次のファイルをまとめて保存します。

| ファイル | 内容 |
| --- | --- |
| `result.json` | 数値、評価理由、解析条件、音源と区間の情報、無音処理と元の位置との対応 |

画面の試聴は各音源の先頭30秒をMP3にしたものです。長い曲でも表示が重くならないようにしています。解析には指定した全区間を使います。

結果ZIPには音源を含めません。音源は別のボタンから全長のWAVとして保存します。

| ボタン | 保存する音源 |
| --- | --- |
| 無音調整後の歌声WAVを保存 | 無音調整後に解析へ使った全区間 |
| 無音調整前の歌声WAVを保存 | 歌声を抽出した直後の全区間 |

将来、無音の扱いや解析帯域を変えて試す場合は、無音調整前のWAVも残しておいてください。

Webの合成例と比べながら、Colabに表示したグラフや保存した `analysis.png` を読んでみましょう。実際の音源の処理と結果の確認はColabで行います。

Colabの実行環境は一時的です。後から使いたい図や結果、比較DBは、セッションを終える前に保存してください。

### 保存した歌声WAVを再解析する

1. 「ファイルをアップロード」から保存済みの全長WAVを取り込み、「今回の音源」の表示を確認します。
2. **「歌声だけの音源です（分離を省略）」をオン**にします。
3. 「曲全体を解析」を選び、解析モードを固定にします。
4. 「無音の調整」で「途中の無音も除く」をオフにします。既に前後の無音を切ったWAVをそのまま使う場合は、必要に応じて前後の除去もオフにします。
5. 「解析を始める」を押します。

波形を保存してあれば、歌声分離やYouTubeからの取得を繰り返さず、新しい包絡処理と周波数範囲で解析できます。旧版で除いた無音を元へ戻すことはできません。結果ZIPの数値だけでは、音声から包絡を計算し直せません。

<a id="reference-db"></a>

## 7 登録曲を比べる・自分のDBへ追加する

### 初期登録された数値の解析結果を確認する

起動時には、13曲の測定結果を数値として登録した参考DBを読み込みます。**DBに音声ファイルや音楽データは含まれていません。** [Webの解析結果一覧](https://shogo-ishikawa.github.io/2026_3Q_M4Th4/vocal-fluctuation-lab/#database)では、曲名・アーティスト名で検索し、固定モードでのβとR²を確認できます。

Colabでは「現在のDBに登録された解析結果」を開きます。現在のセッションで読み込んでいるDBの曲名・アーティスト名・登録区間数を確認できます。自分で追加した後や保存したDBを読み込んだ後は、Webの初期一覧とは内容が変わる場合があります。

初期DBの13曲は、すべてAIで抽出した歌声をもとにしています。今回のColabで抽出したものと、以前に抽出して保存した歌声を再解析したものが含まれます。参考DBの値は、完全な200 Hz包絡から固定0.2〜20 Hz・20秒窓で計算し直したものです。元の自動モードの値と区別しています。Tommy february6の「je t'aime ★ je t'aime」も、新たに歌声分離した音源の結果で登録しています。以前の途中無音を除いた音源の結果は、現在の通常比較へは使いません。

### 登録曲と比較する

1. 「解析モード」で「固定（比較DB用：0.2〜20 Hz）」を選びます。
2. 比較したい登録曲と同じ無音設定、分離方法で音源を解析します。
3. 画面の登録総数と、今回比較できる曲数を確認します。対象外になった条件も表示します。
4. 距離、参考曲、登録曲数を読みます。小さい距離ほど、測定した音量のゆらぎの特徴が近い結果です。

比較するのは、傾き、音量の変動係数、低周波側の割合、スペクトル平坦度の4特徴量です。「声が何%似ている」「同じ歌手である確率」を表す値ではありません。その曲、その区間、その録音の強弱の揺れ方を比べています。

比較には、解析と前処理の記録がそろう結果を使います。以前のAI抽出済みWAVを再解析する場合は、現在の入力時に分離を省略していても、元の歌声はAIで抽出されたものです。抽出・再解析の履歴は内部の記録に残し、条件が合わない結果と同じ音源・同じ区間との自己比較を除きます。

1曲だけではアーティスト全体を代表できません。複数曲をそろえると、一曲だけに偏った比較を減らせますが、録音やミックスの影響まで除去できるわけではありません。

### 自分が解析した曲を追加する

1. 既に保存した自分用DBへ追加する場合は、**解析前に「比較DBを読み込む」からそのJSONを選びます**。読み込みは現在のDBを置き換え、二つのDBを自動で結合する操作ではありません。初期DBへ初めて追加するなら、そのまま進めます。
2. 「解析モード」を固定にします。比較したい曲に合わせて、無音処理と歌声分離の条件もそろえます。初期DBの通常設定は、前後の無音除去がオン、途中の無音除去がオフです。
3. 曲を解析し、抽出した歌声、判定理由、実際の使用帯域を確認します。比較に必要な品質が足りない結果は登録できません。音源が長くても、自動モードのままでは初期DBと条件が合わない場合があります。
4. 「アーティスト名」「曲名」を入力します。自分の録音ならアーティスト名はニックネームなどで構いません。曲名に「練習曲・テイク1」のように書くと、後から区別しやすくなります。
5. 「この結果を比較DBへ追加」を押します。「現在のDBに登録された解析結果」で追加を確認します。
6. 続けて別の曲を登録しても構いません。追加後は、**「比較DBを保存」からJSONをダウンロードします**。保存しないままセッションを終了すると、今回の追加を次回へ持ち越せません。

「結果ZIPを保存」は、その一回の解析図と数値を保存するボタンです。比較用の曲をまとめたDBの保存とは別です。DBを追加・変更したら「比較DBを保存」も押してください。

保存先を分ける場合は、ダウンロード後のファイル名を `my_voice_db_2026-11-11.json` などへ変更できます。次回はColabを準備して「比較DBを読み込む」からそのJSONを選び、「現在のDBに登録された解析結果」を確認します。別のDBへ切り替える前にも、追加済みのDBを保存しておきます。

自分のDBへの追加は、自分が使う比較データを増やす操作です。音源やDBが公開リポジトリへ自動送信されることはありません。公開用の初期DBへ反映したい場合は、結果の条件と内容を別途確認して登録します。

自動モードでは、長さによって帯域やWelch法の窓が変わります。DBへの登録時と問い合わせ時は、固定モードと同じ無音処理の方針、同じ分離方法・モデルの版を使います。v1.2以前のDBは、新しい包絡処理とそのまま比較できません。保存した全長WAVか元音源から再解析して登録し直します。

## 自分の歌声を調べる

伴奏のない自分の歌声も調べられます。スマートフォンの録音アプリなどで、まずは90秒〜数分を録音してみましょう。音割れや周囲の音が少ない状態で、普段どおり歌います。解析に残った歌声が60秒未満の場合は1/fの判定を保留するため、少し余裕のある長さにします。

1. Colabの「音源を選ぶ」から録音を取り込み、「今回の音源」の名前を確認します。
2. 「自分の声を調べる」を開き、目的を選びます。目的を変えるか、「自分の声の設定を使う」を押すと、録音向けの設定になります。
3. 「歌声だけの音源です（分離を省略）」と「曲全体を解析」がオンになることを確認します。前後の無音は除き、途中の無音は残します。自分の歌声だけの録音を使うため、歌声分離は行いません。
4. 「解析を始める」を押します。結果の使用帯域、判定理由、グラフを確認します。

| 目的 | 設定と読み方 |
| --- | --- |
| 1/fゆらぎを調べる | 自動モード。音量変動の傾き、R²、時間を分けた結果を読み、どの帯域で1/fに近い傾向があるかを確かめる |
| 登録曲と比べる | 固定モード。解析と前処理の記録が合う測定結果を比較する。登録総数と今回比較できる曲数を確認する |

比較対象は、今回の解析と前処理の記録が合う結果です。初期DBはすべてAI抽出した歌声の測定値で、自分の伴奏なしの録音と条件を完全に統制した資料ではありません。録音・ミックス・抽出や再解析の履歴の違いも結果に入ります。今回比較できる件数を画面で確認してください。比較対象がない場合も、1/fの判定やグラフは確認できます。

録音の歌い方を変えて、同じ曲の別テイクを比べるのも一つの実験です。同じ長さの同じ箇所を、同じ端末・距離・音量設定で録ると違いを考えやすくなります。結果は、その録音の強弱の変動として読みます。「自分という人が1/fを持つ」という固定的な属性や、声質の似方、歌唱力を判定するものではありません。

録音に伴奏が入っている場合は、この歌声のみ入力の設定を使わず、通常の歌声分離から進めます。解析結果や自分用DBを残したい場合は、上の保存手順でそれぞれ保存します。

## 8 困ったとき

| 状況 | 対応 |
| --- | --- |
| 180秒までしか選べない／新しい操作がない | このマニュアル冒頭のv1.7.1用リンクを開き、準備セルと「解析画面を開く」を実行する。画面上部の版を確認する |
| 選んだ音源が反映されない | 「音源を取り込む（選択が反映されない場合）」のチェックをオンにしてセルを実行する。またはColab内の実パスを指定し、「このファイルを使う」を押す |
| 取り込みを取り消した／失敗した | 以前の選択は解除される。改めて取り込み、「今回の音源」に名前と大きさが表示されてから解析する |
| ファイルが大きすぎる | 上限は512 MiB。最大10分の範囲を使い、必要なら可逆圧縮のFLACなどへ変換する |
| 開始・終了のエラー | 開始より終了を大きくする。音源の長さも確認し、10分を超える曲は区間を指定する |
| YouTube取得に失敗 | 利用できるファイルをアップロードする |
| GPUで失敗 | 処理装置をCPUへ変えて再実行する |
| 無音、強弱の変動不足 | 歌声のある別の区間を選ぶ。抽出した歌声を再生する |
| 無音を除きすぎた | 「無音の調整」でしきい値を下げるか、無音の除去をオフにして再解析する |
| 判定保留 | 理由を読み、区間を長くするか、違う区間と比べる |
| DBへ追加できない | 判定理由、登録名、重複区間の有無を確認する |
| 比較結果が出ない | 同じ固定モード・無音処理・分離方法・モデルの版で実測値を登録する。同じ区間だけのDBでは比較しない |
| 旧版のDBを読み込めない | 保存した全長WAVか元音源をv1.7.1で再解析し、新しいDBへ登録する |
| 帯域で傾きが変わる | 両方の結果を残し、別の区間でも比べる。最も−1に近い方だけを採用しない |

Colab上の画面表示と、実際のColabランタイムで解析を完了したかどうかは [検証記録](validation.md)に記載しています。YouTubeからの音声取得成功は未確認のため、取得に失敗した場合はファイル入力を使ってください。
