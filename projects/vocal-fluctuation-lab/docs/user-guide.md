# 歌声のゆらぎを調べる操作マニュアル

Vocal Fluctuation Labは、歌声の音量が時間とともにどう揺れるかを調べます。まずは歌声のある90秒程度の区間を一つ選び、抽出結果を聴いてから図と数値を確認しましょう。

## 1 Colabの準備

1. [Colab用Notebook](https://colab.research.google.com/github/shogo-ishikawa/2026_3Q_M4Th4/blob/main/projects/vocal-fluctuation-lab/notebooks/vocal_fluctuation_lab.ipynb)を開きます。
2. Googleアカウントへのログインが必要な場合はログインします。
3. 歌声分離にGPUを使う場合は、Colabの「ランタイム」からランタイムのタイプを変更し、利用できるGPUを選びます。利用できないときはCPUでも処理できます。
4. Notebookの最初の準備セルを実行します。ライブラリの取得には時間がかかる場合があります。処理が終わるまで待ちます。
5. 操作画面を表示する次のセルを実行します。

ColabのランタイムやGPUの提供には利用条件と制限があります。画面上で選べる環境を使ってください。設定や依存関係の詳しい説明はNotebookにも記載しています。

## 2 音源を指定

### ファイルから始める

1. 「ファイルをアップロード」を選びます。
2. ファイル選択からMP3、WAV、M4A、FLACなどを選びます。
3. 歌声だけのファイルであれば「歌声だけの音源です（分離を省略）」にチェックを入れます。伴奏入りの音源ではチェックを外します。

ファイルはColabの実行環境へアップロードします。このGitHubリポジトリやPagesの公開サイトへ登録する操作ではありません。自分の録音や、利用できることを確認した音源を使ってください。

### YouTubeから始める

1. 「YouTube URL」を選びます。
2. 動画を一つだけ指定するURLを入力します。再生リストやライブ配信は対象にしません。
3. 開始・終了の秒数を入力して解析します。

公開状態、地域制限、YouTube側の取得制限などで取得できない場合があります。取得に失敗したら、利用できるファイルをアップロードしてください。この機能は取得制限を回避する仕組みではありません。

## 3 開始と終了を秒で指定

「開始（秒）」は音源の先頭を0秒とした開始位置です。「終了（秒）」は解析を終える位置で、解析する長さそのものではありません。

| 調べたい区間 | 開始（秒） | 終了（秒） | 長さ |
| --- | ---: | ---: | ---: |
| 先頭から90秒 | 0 | 90 | 90秒 |
| 40秒から2分10秒まで | 40 | 130 | 90秒 |
| 1分から3分まで | 60 | 180 | 120秒 |

処理できる長さは10〜180秒です。60秒未満ではゆっくりした変動を判断する材料が少ないため、1/fに近いかどうかの判定を保留します。元の音源が終了位置まであることも確認してください。

最初は歌声が続いている90秒程度を選びます。長いイントロや間奏、無音が多い区間を避けてください。歌声のない時間を勝手に削除してつなぐことはせず、元の時間の並びを保って解析します。

## 4 歌声を取り出して解析

1. 「処理装置」で通常は「自動（GPUを優先）」を選びます。
2. 「解析を始める」を押します。
3. 表示される処理の進み具合を見て、完了まで待ちます。初回はAIモデルも取得します。
4. 「元の区間」と「抽出した歌声」を再生します。

歌声抽出はDemucsによる推定です。伴奏が残る場合や、歌声が欠ける場合があります。特に歌声が小さい曲、ハモリの多い曲、エフェクトが強い曲などは抽出結果を耳でも確認します。伴奏が強く残っていれば、結果は歌声だけの変動とは解釈しにくくなります。

GPUのメモリ不足で失敗した場合は「CPU」を選んで再実行できます。CPUでは処理時間が長くなる場合があります。GPUを明示的に使いたい場合だけ「GPU（CUDA）」を選びます。

## 5 結果を読む

### 音量の時間変化

最初のグラフはRMSという音量の目安を時間順に並べたものです。山が高いほど、その短い時間の音の振幅が大きいことを表します。音の高さそのものを描いた図ではありません。

開始・終了の入力は元の音源の先頭を基準にします。一方、グラフの横軸は切り出した区間の開始からの相対時刻です。40〜130秒を指定した場合、グラフは約0〜90秒の範囲を表示します。

### ゆらぎのパワースペクトル

ゆっくりした揺れと速い揺れがどれくらい含まれるかを表します。例えば0.2Hzは約5秒、5Hzは約0.2秒の周期の変化に対応します。声そのものの「100Hzの音」といった高さとは別の周波数です。

両対数の図で、横軸の周波数を10倍にしたときパワーが約10分の1になる傾きが、1/fに対応する−1です。ただし、一本の直線を引けただけでは十分ではありません。

| 表示 | 確認すること |
| --- | --- |
| 傾き β | −1からどのくらい離れているか |
| R² | 対数の点が直線にどのくらい近いか |
| 解析した周波数範囲 | どの速さの揺れを比べたか |
| 区間ごとの傾き | 同じ音源でも時間を分けると大きく変わらないか |
| 判定理由 | 長さ、無音の割合、データ点の不足などがないか |

### 三つの表示

- **指定条件で1/fに近い**：このツールの探索用基準を満たしました。別の区間でも確かめます。
- **1/fに近いとは言えない**：必要なデータがあり、区間による変動も小さいものの、傾きが−1の近くにはありません。
- **判定保留**：短い、ほぼ無音、直線への近似が弱い、区間で結果が大きく変わるなどの理由があります。

この評価は歌唱力、声の魅力、健康への効果を表しません。解析の基準は [方法の説明](method.md)に明記しています。

## 6 結果を保存

「結果ZIPを保存」で、次のファイルをまとめて保存します。

| ファイル | 内容 |
| --- | --- |
| `result.json` | 数値、評価理由、解析条件、音源と区間の情報 |
| `envelope.csv` | RMS包絡と時刻 |
| `spectrum.csv` | ゆらぎのパワースペクトル |
| `binned_spectrum.csv` | 対数周波数ごとにまとめた値 |
| `analysis.png` | 解析図 |

結果ZIPには音源を含めません。「歌声WAVを保存」を押すと抽出した歌声を別に保存できます。

公開ページの「自分の結果JSONを開く」では `result.json` を読み込み、グラフを表示できます。ここで読み込んだファイルはブラウザ内で表示します。音源を再解析したり、比較DBを新たに計算したりする機能ではありません。

Colabの実行環境は一時的です。後から使いたい図や結果、比較DBは、セッションを終える前に保存してください。

## 7 アーティストの参考比較

比較元が未登録のままでは、アーティストの順位を表示できません。初期状態の実アーティストDBは空です。測定していないアーティストの値を自動生成することはありません。

### 比較元のデータを作る

1. 比較元にする曲を解析します。
2. 抽出した歌声と判定理由を確認します。比較に必要な品質が足りない結果は登録できません。
3. 「アーティスト名」「曲名」を入力します。
4. 「この結果を比較DBへ追加」を押します。
5. 別の曲やアーティストでも繰り返します。
6. 「比較DBを保存」で `reference_database.json` を保存します。

### 保存したDBで比べる

1. 「比較DBを読み込む」で保存したJSONを選びます。
2. 比べたい別の音源を解析します。
3. 表示された距離、参考曲、登録曲数を確認します。

小さい距離ほど、音量のゆらぎに関する4特徴量が近い結果です。「同じ歌手の確率」や「声が何%似ている」といった意味ではありません。違う解析条件や分離モデルの結果は混ぜず、問い合わせと同じ音源・同じ区間も比較から除きます。

1曲しか登録していない場合は、その曲の参考値として読みます。複数曲をそろえると、ある一曲だけに偏った比較を減らせます。録音やミックスの違いまで除去できるわけではありません。

## 8 困ったとき

| 状況 | 対応 |
| --- | --- |
| 音源を選べない | 操作画面のセルを再実行し、ファイルを選び直す |
| 開始・終了のエラー | 開始より終了を大きくし、区間を10〜180秒にする。音源の長さも確認する |
| YouTube取得に失敗 | 利用できるファイルをアップロードする |
| GPUで失敗 | 処理装置をCPUへ変えて再実行する |
| 無音、強弱の変動不足 | 歌声のある別の区間を選ぶ。抽出した歌声を再生する |
| 判定保留 | 理由を読み、区間を長くするか、違う区間と比べる |
| DBへ追加できない | 判定理由、登録名、重複区間の有無を確認する |
| 比較結果が出ない | 実測値を登録し、解析条件・分離方法・モデルの版をそろえる。同じ区間だけのDBでは比較しない |

初回公開時点で、Colab上での画面操作とYouTubeからの音声取得成功は未確認です。ローカルで確認した内容は [検証記録](validation.md)を参照してください。
