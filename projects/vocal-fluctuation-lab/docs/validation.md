## v1.3.1：保存済みWAVの取り込み

2026年11月10日、同じLinux / Python 3.12.14環境で144件のPythonテストを通過しました。解析手法は `rms-welch-v2` のままです。

- Colabでは、音源を従来のFileUploadウィジェットへ転送せず、Colab標準の `files.upload` で保存した実ファイルを使います。Googleの公式実装に合わせ、返された実パスと保存先を確認しています。ウィジェット内のボタンとは別に、通常のセルから取り込む補助セルと、ファイル欄に置いた音源の絶対パスを指定する経路も追加しました。
- 回帰テストでは標準転送を模した戻り値を使い、重複名調整後の実パス、ファイル名とサイズの表示、転送中の操作制御、キャンセル・例外・複数選択・存在しないパス・拡張子違い・空ファイル・容量超過を確認しました。失敗後に以前のウィジェット内の音源が誤って使われることはありません。
- 入力上限を512 MiBにしました。10分・44,100 Hz・ステレオ・float32のWAVは約201.9 MiBとなり、従来の200 MiBを超えます。この大きさのファイルを全バイト読み込まずに選択できることを確認しました。解析時間の上限は10分です。
- 保存済み歌声の実パスを選択し、「歌声だけの音源です（分離を省略）」をオンにした場合、そのファイルを分離し直さず解析へ渡すことを確認しました。元のファイルを書き換えません。補助セルは初期状態では実行しません。
- 実際のボタン操作で、121.12 MiB・360秒の保存済み合成歌声WAVをパス指定し、曲全体・固定モードで共通の解析処理と結果表示まで完了しました（5.07秒）。無音調整後は330.1秒、20 Hzまでの傾きは−1.1065、5 Hzまでは−1.1222でした。6ファイル入りの結果ZIPと試聴MP3を作成し、FileUpload値が空のままであること、元WAVのSHA256が変わらないことを確認しました。この試験は歌声のみ入力のため分離を省略しています。

「ファイルを選択できるが認識されない」という現象に対応する転送経路の改善です。利用者のColabで起きた原因や通信サイズの限界は特定できていません。この検証用環境ではGoogleへログインできず、実Colabのブラウザからのファイル転送は未検証です。GitHub ActionsやPagesの完了待ちは行いません。

## v1.3.0：帯域と包絡処理の更新

2026年11月10日、Linux / Python 3.12.14で確認しました。音声の試験には第三者の楽曲を使わず、自作の合成音を使用しています。

- 134件のPythonテストで、入力・無音処理・解析・比較DB・Notebook準備・画面と保存を確認しました。
- 8,000 Hzと44,100 Hzのサンプルレート、100・440・1,000 Hzのキャリア、1・5・10・20 Hzの小さな振幅変調の計24条件で、新しい包絡が変調振幅を±5%以内で保持することを確認しました。これは合成音での確認範囲であり、実際の歌声の測定誤差が常に5%以内という意味ではありません。旧50ミリ秒の箱型RMSで弱まる20 Hzの変調も、新方式では保持できました。
- 白色・ピンク・褐色の変動で振幅変調した音声から、平坦・約−1・約−2の傾きを区別できました。無音、一定の音、短い入力、周期的な変動、性質が途中で変わる入力を安易に1/fとしないことも確認しています。
- 無音調整後の長さが60・90・300・600秒の場合、自動モードの下限はそれぞれ約0.2・0.15・0.08・0.04 Hzになりました。上限は20 Hzです。長い入力では、時間を四等分した各ブロックにもWelch平均用の窓が3個以上あることを、実際の計算呼出しで確かめました。
- 実ウィジェットのボタンから360秒の逆位相ステレオ音源を解析しました。この長時間の確認は歌声のみとして分離を省略しています。無音調整後は330.1秒、自動モードは約0.07271〜20 Hz、窓41.26秒でした。20 Hzまでの結果と同じ下限から5 Hzまでの結果を出力し、日本語グラフ、6ファイルの結果ZIP、帯域比較CSVを保存しました。
- 抽出直後の全長WAV（360秒）を実際に再アップロードし、固定モードの0.2〜20 Hzで再解析できました。音源を選び直すと古い結果・保存ボタンが無効になり、今回のファイルだけを使います。元ファイルは変わりません。異なる解析条件のDB登録を混ぜて比較しないこと、DBの保存と再読込み、秒数リセットも確認しました。
- 3個の試聴プレイヤーのHTMLは合計1,445,346 bytesでした。画面の試聴は先頭30秒のMP3、保存する無音調整前・後のWAVは全長です。グラフの表示外にあるフィルタ阻止域の小さなPSDによって、縦軸が過剰に広がらないことも確認しました。
- PyTorch 2.11.0+cpu / Demucs 4.1.0で16秒の自作合成音を実分離し、新しい包絡処理とJSON保存まで13.89秒で完了しました。主帯域0.75〜20 Hz、比較帯域0.75〜5 Hzで、短いため双方とも判定保留・DB利用不可になりました。
- 音源ボタンの数字非表示は、ipywidgets 8の公式配布JavaScriptのDOM構造に合わせた限定CSSで実装しました。選択中のファイル名を別に表示します。検証用ブラウザではローカルHTMLの表示が制限され、Colabランタイムにもログインできないため、Colab上での最終描画・実行は未検証です。

実際の楽曲における分離品質、コーラスだけを分ける精度、歌手に固有の特徴、全曲の分離にかかる時間は、この合成音試験では検証していません。GitHub ActionsやPages公開の完了待ちは、上記の確認から切り離しています。

## 外部サービスと実測データ

YouTubeの指定動画ではタイトルと全長の取得まで進みましたが、音声区間の取得は配信データを読み取れず失敗しました。そのため、YouTubeからの取得成功を保証していません。画面で失敗理由を確認し、利用できる音声ファイルのアップロードへ切り替えてください。認証や地域制限を回避する処理は含めていません。

実在のアーティストを新しい方法で測定したデータは同梱していません。提出資料の5曲は再解析候補、旧5結果は別方式の記録として分けてあります。新しい参照DBへは、実際に解析して品質条件を満たした結果を登録します。音源や歌声そのもの、モデルの重み、個人のアップロード履歴は公開用ZIPに含めません。

数値の品質条件は教育用の目安です。判定や参照距離は歌手の本人認証、歌唱力や心地よさの評価には使えません。
