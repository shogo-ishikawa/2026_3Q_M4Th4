# Vocal Fluctuation Lab

**音と波の基礎を学び、歌声の音量の時間変化から1/fゆらぎを調べる教材です。** Webで波形やスペクトルの見方を学び、Colabで自分の音源を解析します。公開版は **v1.2.0** です。

[Webで音と波を学ぶ](https://shogo-ishikawa.github.io/2026_3Q_M4Th4/vocal-fluctuation-lab/) · [Colab v1.2.0で解析する](https://colab.research.google.com/github/shogo-ishikawa/2026_3Q_M4Th4/blob/main/projects/vocal-fluctuation-lab/notebooks/vocal_fluctuation_lab_v1.2.0.ipynb) · [操作マニュアル](docs/user-guide.md)

2026年度「計算科学基礎」の学生制作にあった、複数の歌声を取り出して数値で比較する発想を引き継ぎました。元の音声スペクトルの傾きと、音量の時間的なゆらぎを区別し、データが足りないときは判定を保留するようにしています。[制作の背景](docs/student-origin.md)も確認できます。

## 何ができますか

Webでは、音と波、複数の周波数に分けたスペクトル、1/fゆらぎの順に学べます。合成した波形やグラフを動かし、図の変化を確かめられます。

自分の音源を使う解析はColabで行います。次の機能を使えます。

- MP3・WAV・M4A・FLACなどのファイル、またはYouTubeの単一動画URLを入力します。
- 開始と終了を秒で指定するか、「曲全体を解析」で先頭から最後までを選びます。区間の前後に短い余白を付けてDemucsで分離し、解析する部分を正確に切り出します。
- 歌声の抽出後に、前後の無音を標準で除きます。途中の長い無音も除く処理は、必要な場合だけ選べます。
- 元の区間と抽出した歌声を再生し、分離の状態を聴いて確認できます。
- RMS振幅包絡を使い、音量の強弱が時間とともにどう変わるかを調べます。
- パワースペクトル、傾き、当てはまり、時間を分けた場合の違いを表示します。
- 同じ方法で測った比較データを登録し、音量の揺れの特徴が近いアーティストを参考順位として表示できます。
- 図、CSV、解析条件を含むJSONをまとめて保存します。

**「1/fに近い」は、指定した区間・周波数範囲・このツールの基準での評価です。** 歌手の特定、声質の一致率、歌唱力や心地よさを判定するものではありません。

## 初めて使う

初めての方はWebで「音と波 → スペクトル → 1/fゆらぎ」の順に学ぶと、解析図を読みやすくなります。自分の音源を使うときはColabを開きます。自分のPCにPythonやAIモデルを入れる必要はありません。

1. 上の「Colab v1.2.0で解析する」を開きます。
2. Notebookの説明に沿って、準備セルを実行します。GPUを利用できる場合は歌声分離が速くなります。GPUがない場合はCPUを選べます。
3. 次の「解析画面を開く」セルを実行します。画面上部の版と、最大10分の案内、「秒数をリセット（0〜90秒）」「無音の調整」があることを確認します。
4. 「ファイルをアップロード」か「YouTube URL」を選び、音源を指定します。
5. 「開始（秒）」「終了（秒）」を入力します。例えば40秒から130秒なら90秒間です。曲の先頭から最後まで使う場合は「曲全体を解析」を選びます。「秒数をリセット（0〜90秒）」で通常の区間指定へ戻せます。
6. 「解析を始める」を押し、分離後の歌声と結果を確認します。
7. 「結果ZIPを保存」で図と数値を残します。抽出音声は「歌声WAVを保存」から別に保存できます。

曲全体を使う場合は、先頭から音源の終わりまでを読み取ります。処理する音源は10〜600秒（最大10分）です。**解析に残った歌声が60秒未満なら、グラフを表示しても1/fの判定を保留**します。手動で指定する場合は、元の音源が終了秒まであることを確認してください。

標準では、抽出した歌声の前後にある無音を自動で除きます。途中の休符や間奏はそのまま残します。「無音の調整」で「途中の無音も除く（時間を短縮）」を選ぶと、しきい値以下の長い区間も除けます。この場合、前後が連結されるため、元の曲のリズムや時間的な相関をそのまま評価した結果ではありません。加工前後の長さと除いた秒数を確認し、必要に応じて除去をオフにした解析と比べてください。

長い音源では平均に使える区間が増え、推定のばらつきを減らせます。標準の解析帯域は0.2〜5 Hzで、曲を長くしただけで下限の周波数が自動的に下がるわけではありません。曲全体にはイントロ、サビ、間奏などの構成の違いも入るため、**曲全体と、同じ長さで切り出した複数の区間を比べる**使い方を勧めます。

以前の画面に180秒の上限が出る場合や、リセット・無音調整がない場合は、上のv1.2.0用リンクから開き直してください。準備セルは作品のコードを取得し直し、次のセルから新しい画面を開きます。Google Driveへ保存した以前のNotebookを使っている場合も、新しいリンクのNotebookで準備から進めてください。

YouTubeは動画の公開状態、地域制限、取得制限などによって失敗する場合があります。その場合は利用できる音源ファイルをアップロードしてください。自分の録音や、利用の許可を確認した音源を使います。音源や抽出した歌声を、このリポジトリへ登録する必要はありません。

## 比較データベース

初期状態では、**新しい方法で測った実アーティストの比較データは未登録**です。比較機能と、同じ条件で実測値を集める仕組みを用意しています。未測定の数値をアーティスト名に結び付けて表示することはありません。

1. 比較元にしたい曲を解析し、抽出した歌声を聴いて確認します。
2. 「アーティスト名」と「曲名」を入力します。
3. 「この結果を比較DBへ追加」を押します。
4. 複数曲を登録し、「比較DBを保存」でJSONを保存します。
5. 次回は「比較DBを読み込む」から読み込み、別の音源を解析します。

比較するのは、傾き、音量の変動係数、低周波側の割合、スペクトル平坦度の4種類です。同じ解析条件、同じ無音処理の方針、同じ歌声分離方法・モデルの版の結果を使います。同じ音源・同じ区間との比較は除きます。同じ曲の区間数が多いだけで重く扱われないよう、曲ごとに平均してからアーティストを比べます。距離が小さいほど、ここで測った特徴量が近いという意味です。

1曲だけではアーティスト全体を代表できません。録音方法、ミックス、歌う箇所や分離の誤差にも影響されます。比較結果には登録曲数も併記します。詳しくは [比較データの説明](data/README.md)を参照してください。

学生制作で得られた5曲の値は `data/student_legacy_results.json` に、出典と元の計算方法を付けて残しています。元の値は100〜8000Hzの音声スペクトルの傾きなので、新しい時間ゆらぎの比較DBへは混ぜていません。

### 候補の5曲をまとめて再解析する

Notebookの「比較候補の5曲をまとめて準備する」では、候補を順に取得・分離・解析し、品質条件を満たした結果だけを登録できます。通常は実行しない設定です。URLの内容や使える区間を確かめ、必要なときだけ実行してください。途中で取得に失敗しても、保存済みの成功分は残ります。

ローカルでは、作品フォルダから次のコマンドでも実行できます。出来上がった `artist_references.json` を解析画面の「比較DBを読み込む」で選びます。

```sh
python -m vocal_lab.build_references --catalogue data/reference_catalogue.json --output outputs/reference-build --start 40 --end 130
```

## ローカルで実行する

Python 3.11以降とFFmpegを用意し、作品フォルダで仮想環境を作ります。ローカル検証環境はPython 3.12です。初めての方やIntel Macなど依存関係の準備が難しい場合はColabを使ってください。

```sh
python3 -m venv .venv
# macOS / Linux
source .venv/bin/activate
# Windowsでは上の行の代わりに .venv\Scripts\activate
python -m pip install -r requirements-colab.txt
```

LinuxでCPUだけを使う場合は、依存関係の導入前にCPU用PyTorchを選べます。

```sh
python -m pip install torch==2.8.0 --index-url https://download.pytorch.org/whl/cpu
python -m pip install -r requirements-colab.txt
```

作品フォルダ内で次のコマンドを実行します。

```sh
python -m vocal_lab.cli song.mp3 --start 40 --end 130 --output outputs
```

先頭から曲全体を使う場合は `--end` を省略します。音源の終わりを自動で読み取り、10分を超える場合は区間の指定を案内します。

```sh
python -m vocal_lab.cli song.mp3 --output outputs
```

前後の無音を残した場合と比べるには `--no-trim-edges` を付けます。途中の無音も除く場合は `--remove-internal-silence` を付けます。

```sh
python -m vocal_lab.cli song.mp3 --start 40 --end 130 --output outputs --no-trim-edges
python -m vocal_lab.cli song.mp3 --start 40 --end 130 --output outputs --remove-internal-silence --silence-threshold-db -40 --min-silence 0.5
```

途中の除去を使う結果は時間短縮後の参考値として読みます。元音源の時間的な構造を比べたい場合は、途中の除去をオフにして解析してください。

歌声だけのファイルを使う場合は、分離を省略することを明示します。

```sh
python -m vocal_lab.cli vocals.wav --start 0 --end 90 --output outputs --already-vocals
```

YouTubeから取得する場合は `--youtube` を付けます。次のURL部分を実際に使う単一動画のURLへ置き換えてください。

```sh
python -m vocal_lab.cli "https://www.youtube.com/watch?v=ABCDEFGHIJK" --youtube --start 40 --end 130 --output outputs
```

GPUを使わない場合は `--device cpu` を付けます。結果は `outputs/analysis-<識別子>/` に保存します。同じ出力先を使っても、解析ごとに新しいフォルダを作ります。

既に分離済みの音声の解析だけなら、軽い依存定義を使えます。

```sh
python -m pip install -r requirements.txt
python -m vocal_lab.cli vocals.wav --start 0 --end 90 --output outputs --already-vocals
```

関数に渡す値を一つずつ変えて、結果がどう変わるか確かめます。例えば、同じ曲で区間を変える、元の音と分離後を比べる、無音の調整をオン・オフして比べる、複数曲をそろえて比較する、といった実験ができます。解析の中核はNotebookとCLIで共通です。

## 検証の範囲

Python 3.12、PyTorch 2.8.0、Demucs 4.1.0のローカルCPU環境で、合成した入力を指定区間へ切り出し、実モデルで分離して解析結果を保存する処理を確認しています。合成データの評価や入力の検証もテストします。これは実楽曲での分離精度や、アーティスト識別精度を保証する検証ではありません。

Colab上での画面表示と、実際のColabランタイムで解析を完了する確認は区別して記録しています。YouTubeからの音声取得成功も確認できていません。接続先側の条件による失敗時は、ファイル入力で同じ解析を進められます。具体的な実行内容と版は [検証記録](docs/validation.md)を参照してください。
