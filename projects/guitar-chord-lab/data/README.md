# データと正解注釈

音源データは Git に含めません。合成デモはコードで生成し、実際のギター録音は必要なときに取得します。

## フォルダの使い方

| 場所 | 内容 | Git |
| --- | --- | --- |
| `examples/demo_a_annotation.csv` | 合成デモ `demo_a` の正解注釈の例（生成される注釈と同じ内容。テストで一致を確認） | 含める |
| `generated/demo/` | `guitar-chord-lab make-demo` で作る合成デモ（ギター風の音、正解注釈、ドラム伴奏、`manifest.json`） | 含めない |
| `raw/` | 自分の録音やダウンロードしたデータ（例：`raw/guitarset/`） | 含めない |

音源、分離した音、ダウンロードしたデータセット、モデルの重みは Git に追加しないでください。自分たちの録音や公開データを使う場合も、公開・配布してよい範囲を確認してください。

## 正解注釈 CSV の形式

```csv
start_s,end_s,chord
0.000,1.000,N
1.000,3.000,C:maj
3.000,5.000,G:maj
5.000,7.000,A:min
```

- 必要な列は `start_s`、`end_s`、`chord` です。ほかの列（メモなど）があっても読み飛ばします。列名の前後の空白は無視します。
- 文字コードは UTF-8 で保存します（Excel では「CSV UTF-8（コンマ区切り）」を選びます）。Shift_JIS などで保存したファイルは、理由を示すエラーになります。
- 時刻 [秒] は、**注釈したファイルの先頭を0秒**とします。区間は開始を含み、終了を含みません。
- 音源を切り出して解析するときも、注釈は元ファイルの時刻のまま書きます。切り出し位置（オフセット）は解析結果の `analysis.json`、`chords.csv` の `source_start_s` 列（元ファイルでの時刻）、実験設定の `start_s` に記録され、評価のときに自動で合わせます。解析した長さも `analysis.json` に記録され、評価する区間の終わりは予測の最後の時刻ではなく、この長さで決まります。
- 区間は時刻の順に並べ、重ならないようにします。区間と区間の間（注釈のない時間）は評価しません。

### コード名の書き方

| 書き方の例 | 読み込んだ後の名前 |
| --- | --- |
| `C`、`C:maj`、`Cmaj` | `C:maj` |
| `Am`、`A:min`、`Amin` | `A:min` |
| `Bb`、`A#` | `A#:maj` |
| `Ebm`、`D#m` | `D#:min` |
| `N` | `N`（コードなし） |

- 異名同音は**シャープ側**にそろえます（`Db`→`C#`、`Eb`→`D#`、`Gb`→`F#`、`Ab`→`G#`、`Bb`→`A#`、`Cb`→`B`、`Fb`→`E`、`E#`→`F`、`B#`→`C`）。
- 初版で扱うのは12音のメジャー／マイナー（24種類）と N です。
- `C:7`、`C:maj7`、`C/E`、`C:sus4` などの対応外のコードは、**エラーとして報告します**。三和音や N に置き換えません。
- `X`（判定保留）は推定結果だけに使う記号で、正解注釈には使えません。

### N と注釈の欠損

- `N` は「コードがない（無音の）区間」です。
- 注釈が欠けている時間を N として扱いません。注釈のない時間は評価から外します。
- 推定が不確実な区間（判定保留）を正解注釈の N と同じものとして扱いません。

### 検証される内容

読み込み時に、列の不足、数値でない時刻、負の時刻、終了が開始以下の区間、前の区間との重なり・順序の逆転、音源の長さを超える区間（音源と一緒に読み込むとき）、空欄、対応外のコードを確認し、ファイルの行番号付きでまとめて表示します。

## 合成デモ

`guitar-chord-lab make-demo`（または `guitar_chord_lab.synth.write_demo_dataset`）で、次のファイルを `data/generated/demo/` に作ります。

| ファイル | 内容 |
| --- | --- |
| `demo_a_guitar.wav`、`demo_b_guitar.wav` | Karplus-Strong 法で作ったギター風の音（44.1 kHz、各18秒、120 BPM で拍ごとにかき鳴らす） |
| `demo_a_annotation.csv`、`demo_b_annotation.csv` | 生成に使ったコード進行そのものの正解注釈 |
| `drums_120bpm_seed0.wav` | 合成ドラム（バスドラム・スネア・ハイハット風の音、乱数シード0） |
| `manifest.json` | 生成の条件（サンプリング周波数、テンポ、乱数シード、素材の種類） |

合成デモは、プログラムの動作・音名の対応・評価の計算を確かめるためのものです。合成デモでの成功を、実際のギター録音や合奏音源での認識精度として報告しないでください。また、合成デモのギター風の音は Demucs ではギターとして分離されにくいため、分離の効果を調べる素材には使えません。

## GuitarSet（実際のギター録音）

- 出典：Q. Xi, R. Bittner, J. Pauwels, X. Ye, J. P. Bello, "GuitarSet: A Dataset for Guitar Transcription", ISMIR 2018。配布元は [Zenodo](https://zenodo.org/records/3371780)、ライセンスは CC BY 4.0 です。
- `guitar-chord-lab guitarset`（または `guitar_chord_lab.guitarset.prepare_track`）は、配布 ZIP（音源だけで約650 MB）の中から、指定した録音のマイク収録の音（`*_mic.wav`、44.1 kHz）と注釈（`*.jams`）だけを取り出し、`data/raw/guitarset/` に保存します。
- 正解には JAMS の「指示されたコード」（リードシートのコード）を使い、`*_annotation.csv` に変換します。メジャー／マイナー以外のコードを含む録音はエラーにします。
- 指示されたコードとギターが実際に弾いた音は一致しないことがあります。音符の注釈から、3度の音が少なくとも一度弾かれたコード区間の、時間の割合（`third_played_ratio`）を計算できます（3度の音が鳴り続けている時間の割合ではありません）。詳しくは [docs/research-guide.md](../docs/research-guide.md) を参照してください。

## 元素材IDと調整用／評価用の区分

比較実験の設定では、録音ごとに元素材ID（`source_id`）と区分（`split`：`tuning` または `evaluation`）を記録します。同じ録音から作った切り出し・音量違い・分離結果は同じ元素材IDにし、調整用と評価用の両方に入れないでください。`source_id` を省略すると、使う音声ファイル（`guitar` または `mixture`）を元素材とみなします。同じ元素材ID、または同じ音声ファイルが両方の区分に入っていると、設定の読み込み時にエラーになります。
