# 確認の記録（v0.1.0）

2026年10月27日に行った確認の内容と結果です。環境の詳細は [environment.md](environment.md) にあります。

- 確認した場所：Linux のクラウド環境（x86_64、CPU 4コア、GPU なし）
- 環境 A：Colab と同じ版にそろえた環境（Python 3.13.17、torch 2.11.0+cpu、librosa 0.11.0、numpy 2.1.3、demucs 4.1.0）
- 環境 B：最新版の環境（Python 3.13.17、librosa 1.0.0、numpy 2.5.4。Demucs なし）
- 環境 C：Python 3.12.13 と最新版のライブラリ（Demucs なし）

**実際の Google Colab と GPU では確認していません。** 合成音での成功は、実際のギター録音での認識精度の根拠にしていません。

テストで確かめている主な内容：

- 正弦波（倍音なし）の三和音24種類が、すべての区間で正しいコード名になる
- 無音→コード→無音の境界が 1.0 秒・3.0 秒の位置にそろう／コードの変わり目（2.0 秒）がずれない
- 切り出して解析した結果に、切り出し位置を足すと元ファイルの時刻になる
- 全体が無音の入力は N になり、注意を表示する。2 秒未満や時間幅より短い入力はエラーにする
- しきい値を厳しくすると、N ではなく判定保留（X）になり、候補は残る
- 評価：完全一致（1.0）、不一致（0.0）、境界が 0.5 秒・1.0 秒ずれた場合（0.875・0.75）、判定保留（不正解として数え、判定率も下がる）、N の区間での判定保留、予測なし、注釈のない時間（評価しない）、予測区間の重なり（エラー）
- 判定保留を含まない20通りの乱数の例で、評価の値が mir_eval の `majmin` 比較の結果と一致する
- 不正な注釈：列の不足、空のファイル、数値でない時刻、逆転、重なり（対応外のコードの行の後も検出）、対応外のコード、空欄、負の時刻、音源より長い区間。問題を行番号付きでまとめて表示する
- 混合：指定した音量比（−6〜+12 dB）が、音割れ防止の倍率を掛けた後も保たれる
- 時間ずれの推定（110 サンプルの遅れを検出）、元素材単位の分割、比較実験の実行・集計・分離前後の対応付け、合奏録音（mixture）だけの場合
- Demucs 未導入、モデル取得の失敗、guitar を出力しないモデル、メモリ不足の説明。同じ入力・設定のキャッシュの再利用と、入力や設定が違う場合の再計算
- CLI：`demo`、`analyse`（`--separate`・`--start` で元ファイルの時刻を保つこと）、`evaluate`、エラーの表示

## 2. 第1段階：単独音源のコード認識（合成音）

既定の設定での確認です（プログラムの確認であり、実録音の精度ではありません）。

- Karplus-Strong 法の合成音で、24コード × 乱数シード2通り（各3秒、6区間）を解析しました。48通りのうち45通りはすべての区間が正しいコードになりました。残る3通り（C:min、C#:min、F:min）は、6区間のうち1区間が判定保留になり、C:min の1通りではさらに1区間が同主調の C:maj になりました。根音の倍音（5倍音は長3度の音名）の影響と考えられます（推測であり、原因は確かめていません）。
- 合成デモ（`guitar-chord-lab make-demo` で作る各18秒の2本）：`demo_a` は正解率 0.972（判定保留 0.5秒、誤り 0秒）、`demo_b` は正解率 1.000 でした。

## 4. 第3段階：評価と比較実験

### 4.1 合成デモ（`configs/experiment_demo.toml`、2素材・6混合条件、環境 A）

| 条件 | 伴奏 0 dB | +6 dB | +12 dB |
| --- | --- | --- | --- |
| solo（平均） | 0.986 | 0.986 | 0.986 |
| mixture（平均） | 0.695 | 0.389 | 0.250 |
| separated（平均） | 0.305 | 0.264 | 0.111 |

分離後が悪化したのは、3.の理由（合成音が guitar に分けられない）によると考えられます。分離後の音が全体で無音しきい値を下回り、すべて N になった条件もありました。プログラムが最後まで動くことの確認であり、分離の効果の評価ではありません。

### 4.2 GuitarSet の実ギター録音＋合成ドラム（5素材・15混合条件、環境 A）

`guitar-chord-lab guitarset` で取り出した5本（奏者01〜05、各録音の先頭20秒、`third_played_ratio` 0.937〜1.0）に、120 BPM の合成ドラムを混ぜました。同じ内容を CLI と Notebook 3 で実行し、同じ値になりました。

| 条件 | 伴奏 0 dB | +6 dB | +12 dB |
| --- | --- | --- | --- |
| solo（平均 ± 標準偏差） | 0.482 ± 0.225 | 同左 | 同左 |
| mixture | 0.417 ± 0.169 | 0.280 ± 0.190 | 0.161 ± 0.155 |
| separated | 0.485 ± 0.242 | 0.482 ± 0.236 | 0.469 ± 0.231 |
| 分離後 − 分離前（平均、最小〜最大） | +0.068（−0.087〜+0.206） | +0.202（+0.069〜+0.378） | +0.308（+0.129〜+0.716） |

- 全15条件で、混合音・分離音と単独ギターの時間ずれは 0 ms でした。
- 伴奏 0 dB では、分離後に正解率が下がった録音が2本ありました（−0.006、−0.087）。
- 単独ギターでも正解率は録音によって 0.236〜0.726 と大きく異なりました。
- 素材は5本だけで、伴奏は和音を持たない合成ドラムです。この結果は道具の動作確認であり、研究の結論ではありません。

### 4.3 素材の選び方についての確認

- 最初に選んだ5本（奏者01の `Rock3-148-C` など）では、単独ギターの正解率の平均は 0.377 ± 0.215、分離前後の差の平均は +0.050、+0.056、+0.124（伴奏 0、6、12 dB）でした。
- 単独ギターでも正解率が低い録音を調べると、奏者01の `Rock3-148-C` は、ほとんどの区間で根音だけを弾いていました（演奏から推定したコード注釈が `C:(1)/1` など）。指示されたコード（正解）と、実際に弾いた音が一致していませんでした。
- GuitarSet のメジャー／マイナーの伴奏録音120本（全体の長さ、既定の設定）で、3度の音が弾かれている時間の割合と、単独ギターの正解率の関係を確認しました。

| `third_played_ratio` | 録音数 | 正解率の平均 |
| --- | --- | --- |
| 0.9 以上 | 90 | 0.640 |
| 0.5 以上 0.9 未満 | 19 | 0.467 |
| 0.5 未満 | 11 | 0.276 |

この確認の後に、注釈だけを使う選定規則（[research-guide.md](research-guide.md) の 4.4 と 8.）を決め、4.2 の5本を選び直しました。規則は推定結果を条件に含めていませんが、評価用の録音の結果を一度見ています。
