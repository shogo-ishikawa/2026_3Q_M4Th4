# 比較実験の手順と注意点

研究の問いと実験計画は [research-plan.md](research-plan.md) にあります。この文書では、実装した道具を使って比較実験を行う手順と、結果を解釈するときの注意点をまとめます。

## 1. 実験の流れ

1. 素材（単独ギター録音と正解注釈、伴奏）を用意する
2. 実験設定ファイル（TOML）を書く
3. 調整用（tuning）の素材だけで、解析設定を決める
4. 決めた設定を固定し、評価用（evaluation）の素材で1回評価する
5. 素材別・条件別の結果と「分離後 − 分離前」の差を確認し、限界とあわせて報告する

コマンドの例（作品フォルダ `projects/guitar-chord-lab` で実行）:

```bash
# 合成デモでの動作確認（分離の評価には使えません）
guitar-chord-lab make-demo
guitar-chord-lab experiment configs/experiment_demo.toml

# GuitarSet の実ギター録音5本＋合成ドラム
guitar-chord-lab guitarset
guitar-chord-lab experiment data/raw/guitarset/experiment_guitarset.toml --split evaluation

# Demucs を使わずに solo と mixture だけを比べる
guitar-chord-lab experiment configs/experiment_demo.toml --conditions solo,mixture
```

Notebook では [03_comparison_experiment.ipynb](../notebooks/03_comparison_experiment.ipynb) が同じ関数を呼びます。

## 2. 比べる条件

| 条件 | 内容 |
| --- | --- |
| `solo` | 正解注釈の付いた単独ギター。比較の基準であり、正解ラベルとしては使いません |
| `mixture` | ギターに伴奏を混ぜた音（`artificial`）、または実際に合奏を録音した音（`recorded`） |
| `separated` | `mixture` から Demucs（htdemucs_6s）で取り出したギター |

3条件とも同じ認識器・同じ設定（`[analysis]`）で解析します。3つの音は同じ録音の同じ位置から切り出し、同じサンプリング周波数（44100 Hz、モノラル）にそろえてから解析します。分離した音は入力と同じ長さで出力されることを確認し、単独ギターとの時間のずれを相互相関で測って `lag_vs_solo_ms` に記録します。

## 3. 設定ファイルの書き方

例は [configs/experiment_demo.toml](../configs/experiment_demo.toml) です。相対パスは、設定ファイルのあるフォルダを基準にします。

| 表 | 主な項目 |
| --- | --- |
| `[experiment]` | `name`、`output_dir`、`seed`、`conditions`、`accompaniment_db`（伴奏の音量の一覧）、`mix_sample_rate`、`peak_limit`、`save_audio`、`save_figures` |
| `[separation]` | `model`（guitar を出力するモデル）、`device`（auto / cpu / cuda）、`shifts`、`overlap`、`segment`、`cache_dir` |
| `[analysis]` | コード認識の設定（[analysis_default.toml](../configs/analysis_default.toml) と同じ項目） |
| `[[recordings]]` | `id`、`source_id`（元素材ID）、`split`（tuning / evaluation）、`material`（synthetic / real）、`guitar`、`mixture`、`annotation`、`start_s`、`duration_s` |
| `[[accompaniments]]` | `id`（伴奏ID）、`path`、`material`、`offset_s`（伴奏のどこから使うか） |

### 伴奏の音量の定義

`accompaniment_db = 20 × log10( 伴奏のRMS ÷ ギターのRMS )` [dB] です。RMS は無音の部分も含めた切り出し全体で計算します。混ぜた後の最大振幅が `peak_limit`（既定0.99）を超えた場合は、混合音全体に同じ倍率を掛けて小さくします。ギターと伴奏に同じ倍率が掛かるので、指定した音量比は変わりません。実際に使った倍率（`clip_guard_gain`）と、混ぜた後に測った音量比（`measured_db`）を `items.csv` に記録します。

## 4. 素材を追加する

### 4.1 自分で録音した単独ギター

1. 録音（WAV 推奨）を `data/raw/<フォルダ名>/` に置きます。Git には追加されません。
2. 正解注釈 CSV（`start_s,end_s,chord`）を作ります（次の 4.3 を参照）。
3. 設定ファイルに `[[recordings]]` を追加します。同じ録音から複数の部分を切り出すときは、`id` を変え、`source_id` を同じにします。

### 4.2 実際の合奏録音

ギターを含む合奏を録音したファイルは、`guitar` の代わりに `mixture` に指定します。人工的な混合を行わず、`mixture`（`recorded`）と `separated` の2条件を比べます。同じ演奏の単独ギターのトラック（マルチトラック録音など）があれば、`guitar` にも指定すると `solo` も比べられます。

### 4.3 正解注釈 CSV

```csv
start_s,end_s,chord
0.000,1.000,N
1.000,3.000,C:maj
3.000,5.000,A:min
```

- 時刻 [秒] は、注釈したファイルの先頭を0秒とします。区間は開始を含み、終了を含みません。
- 切り出して使うときも、注釈は元ファイルの時刻のまま書きます。実験では `start_s`、`duration_s` に合わせて自動で切り取ります。
- コード名は `C:maj`、`A:min`、`N` の形が基本です。`C`、`Am`、`Bb`、`Ebm` のような書き方も読み込めます。異名同音はシャープ側に統一します（例：`Db` → `C#:maj`、`Bbm` → `A#:min`）。
- `N` は「コードがない（無音）」区間です。注釈を付けていない時間は評価しません。N と同じ意味にはしません。
- `C:7`、`C:maj7`、`C/E`（転回形）、`C:sus4` などは**対応外としてエラー**になります。三和音や N に勝手に置き換えません。
- 区間の重なり、順序の逆転、負の時刻、音源より長い区間、空欄も、行番号付きのエラーとして表示します。
- 単独ギターの推定結果を正解として使ってはいけません。

### 4.4 GuitarSet を使う

GuitarSet（Xi ほか、ISMIR 2018、CC BY 4.0）は、6人の奏者が5つのスタイルで演奏したギター録音と注釈のデータセットです。`guitar-chord-lab guitarset` や `guitar_chord_lab.guitarset` の関数は、Zenodo の配布ZIPから必要な録音（マイク収録、44.1 kHz）と注釈（JAMS）だけを取り出します。

- 正解には JAMS の「指示されたコード」（リードシートのコード）を使います。演奏から推定したコード注釈は転回形や7th等を含むため使いません。
- 伴奏（comp）録音のうち、指示されたコードがメジャー／マイナーだけでできているのは120本（20曲 × 6人）です。
- 指示されたコードと、ギターが実際に弾いた音は一致しないことがあります。例えば奏者01の `Rock3-148-C` は、ほとんどの区間で根音だけを弾いており、メジャーとマイナーを分ける3度の音が鳴っていません。音符注釈から「3度の音が弾かれている時間の割合」（`third_played_ratio`）を計算して記録し、0.9 未満の録音には注意を表示します。
- 配布物や論文で使うときは、出典（`guitar_chord_lab.guitarset.CITATION`）を明記してください。

## 5. 調整用と評価用の分け方

- 分割は**元素材（`source_id`）単位**です。同じ録音の切り出し、音量違い、分離結果を両側に入れません。設定ファイルを読み込むときに、同じ `source_id` が両側に入っていればエラーにします。
- 素材が多いときは `guitar_chord_lab.experiment.assign_splits_by_source(source_ids, tuning_fraction, seed)` で、元素材IDを乱数シード付きで分けられます。
- GuitarSet では奏者単位で分けるのが安全です。同じ奏者の録音を両側に入れると、奏者の癖に合わせた設定を選んでしまうおそれがあります。
- 解析設定は調整用の結果だけを見て決め、評価用は決めた設定で最後に1回だけ評価します。

## 6. 指標と出力

| 指標 | 定義 |
| --- | --- |
| `accuracy`（正解率、主指標） | 正解コードと予測が一致した時間 ÷ 評価対象の時間 |
| `decided_ratio`（判定率） | 判定保留でも予測なしでもなかった時間 ÷ 評価対象の時間 |
| `correct_s`、`wrong_s`、`undecided_s`、`missing_s` | 正解・誤り・判定保留・予測なしの時間 [秒] |
| `difference` | 同じ録音・伴奏・音量での `separated` の正解率 − `mixture` の正解率 |

時間は、正解区間と予測区間が**重なっている時間**から計算します。判定保留と予測のない時間は評価対象に含めたまま不正解として数えます。評価の計算は、判定保留を含まない場合について mir_eval の `majmin` 比較と同じ値になることをテストで確認しています。

| 出力ファイル | 内容 |
| --- | --- |
| `items.csv` | 1行＝1つの録音・条件・伴奏の音量。処理時間、分離の時間とキャッシュ利用の有無、時間ずれを含む |
| `paired_differences.csv` | 同じ録音の分離前後の対応付け |
| `summary_by_condition.csv`、`summary_differences.csv` | 平均、標準偏差、最小、最大、録音数、元素材数 |
| `experiment.json` | 設定、件数（元録音数・切り出し数・人工混合の条件数・合奏録音数）、ライブラリの版、コミット |
| `summary.png` | 条件別の正解率と分離前後の差（人工混合のみ） |
| `items/<録音>/...` | 条件ごとの推定結果（`chords.csv`、`analysis.json`）と音（`mixture.wav`、`separated_guitar.wav`） |

## 7. 既定の解析設定の決め方

既定値（[analysis_default.toml](../configs/analysis_default.toml)）は、GuitarSet の**奏者00の伴奏録音20本**（指示されたコードがメジャー／マイナーだけのもの、各録音の全体）を調整用として、次の比較だけで選びました。奏者01〜05の録音は選択に使っていません。

| 比べた設定（ほかは既定値） | 正解率の平均（20本） |
| --- | --- |
| 3音テンプレート（倍音なし）／倍音を4つ・6つ加えたテンプレート（判定保留なし、平滑化3） | 0.713 ／ 0.704 ／ 0.692 |
| 時間幅 0.25・0.5・1.0 秒（平滑化3、判定保留なし） | 0.684 ・ 0.713 ・ 0.659 |
| 平滑化 1・3・5（時間幅0.5秒、判定保留なし） | 0.660 ・ 0.713 ・ 0.701 |
| CQT ／ STFT のクロマ（時間幅0.5秒、平滑化3、判定保留なし） | 0.713 ／ 0.588 |
| `min_margin` 0・0.005・0.01・0.02（`min_score` 0.5） | 0.713 ・ 0.687 ・ 0.665 ・ 0.618（判定率 0.993 ・ 0.927 ・ 0.878 ・ 0.788） |

- 倍音を加えたテンプレートは改善しなかったため、最も単純な3音テンプレートを使います。
- 判定保留を使わない設定（`min_margin = 0`）が最も正解率は高くなりますが、「決めきれない区間」を知らせるために `min_margin = 0.01` を既定値にしました。既定値は正解率を最大にする値ではありません。

## 8. 開発中に確認したこと（結論ではなく、動作確認の記録）

- **合成デモと Demucs**：合成デモのギター風の音（Karplus-Strong 法）は、htdemucs_6s では主に piano・other・drums に分けられ、guitar にはほとんど入りませんでした（入力 −19.2 dBFS に対し guitar −45.2 dBFS）。実際のギター録音（GuitarSet）では、ほぼすべてが guitar に入りました。合成デモは分離の効果を調べる素材には使えません。
- **素材の選び方**：最初に選んだ例（奏者01の `Rock3-148-C` を含む5本）では、単独ギターの正解率が低い録音がありました。原因を調べると、根音だけを弾いている録音でした。そこで GuitarSet のメジャー／マイナーの伴奏録音120本について、`third_played_ratio` と単独ギターの正解率の関係を確認しました（0.9 以上の90本で平均 0.640、0.5 未満の11本で平均 0.276）。この確認の後で「3度の割合が0.9以上」という選定規則を決めたため、規則は推定結果を条件に含めていませんが、評価用の録音の結果を一度見ています。厳密な実験では、選定規則を先に決めてから評価してください。
- 5録音・伴奏3段階での実行結果は [verification.md](verification.md) にあります。小さな動作確認であり、研究の結論ではありません。

## 9. 結果を解釈するときの注意

- 人工的に混ぜた音の結果と、実際の合奏録音の結果を区別して報告します。
- 合成ドラムは和音を持たない伴奏です。ベースやキーボードなど、和音の音を鳴らす伴奏では結果が変わる可能性があります。
- 結果は、使った音源、分離モデル（htdemucs_6s）、コード認識器（3音テンプレートとクロマの類似度）、設定の範囲で述べます。
- 正解率の差は、録音によるばらつきと一緒に示します。元録音数と混合条件数を分けて報告します（例：「5素材・15混合条件」）。
- 分離で悪化した条件も記録します。原因の推測と、実験で確認できた事実を分けて書きます。
- 類似度は正解する確率ではありません。「確信度」「確率」と呼ばないでください。
