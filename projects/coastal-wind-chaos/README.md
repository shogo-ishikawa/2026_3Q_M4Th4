# 海辺の風は何時間先まで予測できるか――機械学習とカオスから考える予測可能性

海辺の風向きを、単純な予報（基準予報）と機械学習で何時間先まで予測できるかを調べ、予測が外れる原因を考えるPython教材です。あわせて、ローレンツ系で「カオス（初期値鋭敏性）」を体験します。Pythonの変数・条件分岐・繰り返し・自作関数を学んだ人を対象とし、機械学習や気象学の知識は前提にしません。

> **実験は2種類で、別のものです。**　風向きの予測（実験1〜3）で分かるのは、与えた入力・モデル・学習期間・評価指標のもとでの**実用的な予測性能**です。誤差が増えることを見ても、それだけで「カオスの壁を見つけた」「この地点の物理的な予測限界は何時間だ」とは言えません。ローレンツ系の実験（実験4）は、カオスとは何かを別に学ぶためのものです。

## 学習の目標

1. 風向きには0°と360°の境界があり、ふつうの数とは扱いが違うことを理解する。
2. 基準予報（持続予報・気候値予報・24時間周期の持続予報）を比較の基準にして、機械学習の効果を評価する。
3. 季節・日周期の情報と、過去・直近の観測情報の役割を比べる。
4. 予測時間を延ばしたとき、精度がどう変わるかを調べる。
5. 予測が外れる原因として、入力の不足、モデルの不足、観測誤差、カオスを区別する。
6. 合成データで学んだ方法を、自分の地元の気象庁データに使う。

## 実験の設計

### 予測の問題と時間の分け方

予測起点 t（予報を出す時刻）までの観測だけを使って、対象時刻 t + h の風を直接予測します。毎時、新しい観測を受け取って予測を出し直す場面を考え、t から t + h までの途中の観測は使いません。予測時間 h ごとに別のモデルを学習します。

- **分割**：3年分の合成データは、**1年目＝学習、2年目＝検証、3年目＝最終テスト**に分けます（暦の上の1年ずつ。`split.mode = "years"`）。最後の N 日で分ける分割（`"last_days"`）も、明示的な別の設定として使えます（自分のデータが3年分ほどないとき）。
- **境界をまたぐ行**：学習の行の対象時刻が検証期間に入る行と、検証の行の対象時刻が最終テスト期間に入る行は使いません。
- **段階ごとの前処理**：検証の段階では1年目だけ、最終テストの段階では1〜2年目だけから、気候値（基準予報と入力の両方）、使う任意の列（気温・気圧・日照）、標準化を決めます。欠けた値の補完はせず、欠けた行は使いません（理由と件数を表示します）。
- **選ぶのは検証期間だけ**：統合モデルの設定（線形回帰、深さ2・3・6の勾配ブースティング）は、検証期間の3時間先の誤差で選び、最終テスト期間では選びません。予測の表し方を決める実験1も検証期間で比べます。
- **共通の予測起点**：予測時間を比べるときは、72時間先まで同じ期間に収まる予測起点だけを使い、どの予測時間でも同じ予測起点で評価します。同じ予測時間の手法どうしは、同じ行で評価します。
- **設定**：`configs/*.toml` の `[models] lags`（u, v の「何時間前」）と `[split] max_horizon`（共通の予測起点を決める最長の予測時間。既定72）は、統合モデルの選択、実験1〜3、補足の比較、入力の確認（`input_columns.csv`。予測時間は、実行する実験2、なければ実験3の最短、なければ実験1のもの）のすべてに同じ値を使い、`results/run_info.json` の `model_options` に記録します。分割の図（`time_split.png`）の濃い部分は `max_horizon` の長さで、図にもその値を書きます。予測時間が `max_horizon` より長い設定は、計算を始める前に止めます。

### 入力（特徴量）と基準予報

| この教材の名前 | 元の仕様の名前 | 入力 |
| --- | --- | --- |
| `calendar`（季節・日周期） | global_only | 対象時刻 t + h の時刻・季節の sin・cos、学習期間だけから計算した月×時刻の平均の u, v（`clim_u`, `clim_v`） |
| `recent`（過去・直近の観測） | local_only | t と1, 2, 3, 6, 12, 24時間前の u, v、u, v の1時間・3時間の変化、t までの24時間の平均の u, v、気温（t と1, 2, 3, 6時間前、1時間・3時間・24時間の変化）、気圧（t、1時間・3時間の変化）、日照（その1時間の値と、その日の t までの合計）。気温・気圧・日照は、学習期間に半分以上ある場合だけ使う |
| `calendar+recent`（統合） | combined | 両方 |

どれも1地点の時間的な情報の区分で、広い範囲の大気の状態を観測した値ではありません。月×時刻の平均の風は、基準予報の「気候値予報」と同じ値ですが、統合モデルなどでは入力として使います（どちらも学習期間だけから計算）。

変化（t の値 − 1時間前・3時間前の値）は「何時間前」の値の差と同じ情報ですが、決定木（勾配ブースティング）は入力を1つずつ見て分けるので、差を入力として明示します。u, v の変化は、`lags` にその時間（1, 3）が含まれるときだけ作ります（使わない「何時間前」の値が、変化を通して入らないように）。

基準予報は3つです。

- **持続予報**：t の風がそのまま続く
- **気候値予報**：学習期間の同じ月・同じ時刻の平均の風
- **24時間周期の持続予報**：t 以前で対象時刻と同じ時刻の観測、つまり t + h − 24 × ⌈h/24⌉ の観測を使う（直近の観測済みの24時間が繰り返すと考える）。h = 25, 48, 72 でも t より後の観測は使いません

### 評価

| 指標・件数 | 意味 |
| --- | --- |
| `mae_deg` | 角度の平均絶対誤差（度）。対象時刻の風向が決まる行（静穏・欠測を除く）で計算する |
| `within_45_pct` | 誤差45°以内の割合（%） |
| `vector_rmse_ms` | 予測と観測の風ベクトル（u, v）の差の二乗平均平方根（m/s）。静穏（u = v = 0）も含める。風向だけを予測する手法（角度の直接回帰、悪い例）は対象外（NaN）。未来の観測の風速を使って風向だけの予測からベクトルを作ることはしない |
| `n_test`, `n_vector` | 角度とベクトルの評価件数 |
| `n_undefined`, `undefined_pct` | 予測の向きが決まらない件数と割合（予測した風ベクトルが0のとき。例：予測起点が静穏のときの持続予報）。行は除かず、角度の誤差を90°（向きを一様ランダムに選んだときの期待誤差）、45°以内の判定を「外れ」として数える |

評価から外す行は、観測と入力だけで決めます。手法の予測によって行を外すことはしません。

### 4つの実験

| 実験 | 内容 | 期間 |

| 1：角度の罠 | 337.5°と22.5°の算術平均（180°）とベクトル平均（0°）。同じ入力（統合）・同じ期間・同じモデル設定・同じ学習行で、u, v を回帰する方法と角度を直接回帰する方法を比べ、観測した風向ごとの誤差で北付近の挙動を見る。対象時刻が静穏の行は風向が決まらず角度の回帰に使えないので、この比較では u, v の回帰の学習からも外す（ほかの実験の u, v の予測では静穏も学習に使う）。入力もモデルも違う「悪い例」は参考に載せるだけ | 検証 |

- **情報の役割**：季節・日周期だけでは気候値予報とほぼ同じです（入力に同じ月×時刻の平均が入っているため）。過去・直近の観測は短い予測時間でよく効き、予測時間が延びると効果が小さくなります。このデータの3時間先では、季節・日周期の情報を加えた上乗せは約1°でした。
- **予測時間を延ばす**：統合モデルの誤差は増え、気候値予報の水準（約50°）に近づきます（72時間先でもまだ少し小さい）。誤差が90°まで増えるわけではありません。持続予報の24時間先・48時間先の誤差が12時間先・36時間先より小さいのは、**日周期**で同じ時刻に似た風が吹くためです。カオス的な細かい情報が回復したわけではありません。24・48・72時間ちょうどでは、24時間周期の持続予報は持続予報と同じ観測（t の値）を使います。
- **90°の線**：図の90°の線は「**独立な一様ランダム方向予測の期待誤差**」です。あらゆる予測の限界値ではありません。風向に偏りがあれば、気候値予報などは90°より小さくできることが多く、海風と陸風が入れ替わる時間差では、持続予報が90°を超えることもあります（周期成分だけのデータでは12時間先で約109°）。

**実験4（ローレンツ系、時間は無次元）**：初期誤差を10分の1にしても、距離が許容誤差1.0に達するまでの時間は約2.5しか延びませんでした。距離の対数の傾きは約0.90、Benettin法による最大リアプノフ指数の推定値は約0.91（fast）・約0.905（full）で、文献値（約0.906）に近い値です。積分の刻みを 0.01 から 0.005（full ではさらに 0.0025）に小さくしても、予測できる時間の中央値の差は fast で最大約0.6、full で約0.25 以内でした。Benettin法の推定値は 0.90〜0.93 の範囲で、有限の時間で平均する推定のばらつきと考えられます。

合成データの成分を変えると（補足のシナリオ比較）、原因の違いが見えます。周期成分だけのデータでは、気候値予報と機械学習の誤差はどの予測時間でも約11°で、残るのは主に観測誤差と16方位の丸めの分です。不規則成分（AR変動）を加えると、誤差は予測時間とともに増え、半日ほどで気候値予報と同じ水準（約32°）で頭打ちになります。これは確率的な変動による予測の難しさで、カオスとは別のものです。

## 限界と注意

- 合成データは、簡単な式と乱数で作った現象のモデルです。数値予報のように大気の流れを計算しているわけではありません。海風が南から吹くのは、この仮想地点の設定です。
- 風向き予測の結果は、その入力・モデル・学習期間・評価指標での実用的な性能です。物理的な予測限界や「カオスの壁」を示すものではありません。合成データの時間の尺度を調整して12〜48時間程度で当たらなくなるようにしても、それは実際の気象の普遍的な限界ではありません。テストは、統合モデルが必ず勝つこと、誤差が90°に達すること、24時間ごとに誤差の谷ができることを合格の条件にしていません。
- 安定なAR過程は、相関のある確率的な変動です。決定論的なカオス（ローレンツ系）とは別のものです。AR変動を加えたデータで誤差が頭打ちになるまでの時間（約半日）は、データを作るときに選んだ `ar_phi` や `ar_strength`（周期成分と比べた強さ）などで決まる設定値です。
- この3変数のローレンツ系では、初期誤差を小さくすれば予測できる時間は（対数的にゆっくりですが）いくらでも延ばせます。大小さまざまな規模の運動がある大気では、初期誤差を小さくしても延ばせない限界があると考えられています（Lorenz, 1969）。実際の大気の予測可能性は、数値予報モデルを使った研究で調べられています（例えば Zhang et al., 2019 は、現在の技術での「実用的な」予測可能性と、初期値の誤差をほぼなくしても残る「本質的な」予測可能性を区別しています）。
- 前線は外から決まるランダムな時刻に来ます。予兆を0にすると、その地点の過去の観測だけでは到来を当てられません。
- **16方位の丸め**：観測値の風向は16方位（22.5°刻み）に丸められています。丸め前の連続的な真の風向（観測誤差なし）と丸めた観測の差は、真の風向が各方位の幅の中で一様に散らばっていると仮定すると、平均 22.5 ÷ 4 ≈ 5.6° です（既定の合成データで観測誤差を0にすると約5.65°）。これは「真の風向」との比較です。評価では丸めた観測値を正解にしているので、連続的な角度で予測する機械学習は、予測が真の風向と完全に一致しても観測値とは平均5〜6°ずれます。持続予報は16方位の観測をそのまま予報にするので、風向が変わらなければ観測値に対する誤差が0°になり、その分だけ有利です。統合モデル（線形回帰）の予測を16方位に丸めてから評価すると、既定の合成データの最終テスト期間では、fast の9通りの予測時間で誤差が0.3〜1.1°ほど小さくなりました（予測時間が短いほど大きい傾向）。
- 単一地点の観測だけを入力にしています。周りの地点の観測や数値予報は使っていません。
- 気象庁の実データで確かめたのは、24〜72時間分の短いファイルの読込までです。数年分の実データで実験1〜3を通して実行することは確認していません（気象庁のサイトから取得するデータの量を最小限にしたため）。気象庁形式の合成CSVを2つのファイルに分けて `--data` で渡す使い方は、テストで確かめています。
- テスト期間の成績を見ながら条件を何度も選ぶと、テスト期間に合わせた選択になります。この教材では、設定の選択は検証期間で行います。
- 実データを使うときの注意（品質情報、均質番号、データの修正、アメダスの日照時間の推計値など）と利用条件は [data/README.md](data/README.md) にまとめています。自分で作った将来の予想を他の人に向けて繰り返し公表すると、気象業務法の予報業務の許可が必要になることがあります。この教材では、過去のデータで学習と評価をするだけにしてください。
