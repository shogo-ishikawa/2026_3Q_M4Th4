# 海岸の風速・風向予報ラボ：出力形式

Colabで計算した結果を保存し、同じ条件で読み直したり、Web側の表示に渡したりするための形式です。ファイルに含まれる数値は、その実行で使用した地点・期間・条件の結果です。

## 結果ZIPの内容

| ファイル | 内容 |
| --- | --- |
| `metadata.json` | スキーマの版、モード、データの出典、地点、解析条件、時刻の基準、実行環境 |
| `predictions.csv` | 予測起点・対象時刻・モデルごとの予測と観測。評価できない行も保持する |
| `summary.csv` | 地点・モデル・予測時間先ごとの誤差と件数 |
| `errors_by_month.csv` | 月別の誤差と件数 |
| `errors_by_hour.csv` | 時刻別の誤差と件数 |
| `errors_by_direction.csv` | 観測風向の区分別の誤差と件数 |
| `errors_by_speed_band.csv` | 観測風速帯別の誤差と件数 |
| `skill.csv` | 同じ行で比較した持続予報からの改善度と95%区間 |
| `observations.csv` | その解析で使った観測の時系列。観測を入力した場合に保存する |
| `validation_predictions.csv` | モデルの選択に使った調整期間の予測。過去検証で保存する |
| `selection_scores.csv` | 調整期間で各候補を比較した風速MAEと件数 |
| `forecast_history.csv` | 取得時刻・計算回を保持した気象予報の履歴。予報モードで保存する |
| `learning_curve.csv` | 学習期間の長さを変える追加実験を選んだ場合の比較表 |
| `models.joblib` | この実行で学習したモデル。同じ環境で保管するためのファイル。Colabに取り込む機能はない |
| `figures/` | その実行で作成したグラフ |
| `README.txt` | 出典と各ファイルの読み方 |

評価できる観測がない場合、誤差表は空になるか、指標が空欄になります。0を「未評価」の代わりには使いません。選んだモードで作らないファイルは含まれません。

## 時刻と単位

CSVの `issue_time`、`target_time`、観測履歴の `observed_at` は日本標準時（JST、`Asia/Tokyo`）です。書き出す日時には `+09:00` を付けます。内部処理のタイムゾーンなし日時もJSTとして扱います。API取得時刻や初期時刻がUTCの場合は、その基準をメタデータの項目名と値に明示します。

風速・風の成分・風速誤差の単位はm/sです。風向は北0°から時計回りの度、割合は%です。`u` は東向き、`v` は北向きの成分です。気象の風向は「吹いてくる向き」を表すので、北風は `v` が負になります。

## `predictions.csv`

1行は、1地点・1モデル・1予測起点・1対象時刻の組です。同じ対象時刻でも、起点やモデルが違えば別の行になります。

| 列 | 意味 |
| --- | --- |
| `issue_time` | 予測起点。機械学習では入力の基準時刻。API予報での意味はメタデータで識別する |
| `target_time` | 予測の対象時刻 |
| `horizon_h` | `target_time − issue_time` の時間数 |
| `station` | 地点の識別名 |
| `model` | 予測手法・気象モデルの識別名 |
| `observed_u_ms`, `observed_v_ms` | 対象時刻に観測された風の成分 |
| `predicted_u_ms`, `predicted_v_ms` | 予測した風の成分 |
| `observed_speed_ms` | 元の観測風速。観測を入力していない場合は空欄 |
| `predicted_speed_ms` | 予測風速。数値予報では提供元の風速、機械学習では予測成分の大きさ |
| `excluded` | 評価から外した理由。空欄は、その列に除外理由がないことを表す |

`excluded` が空欄でも、未来の行は観測がないため評価できません。読み込み側は除外理由だけでなく、観測・予測がそろっているかも確認します。欠測はCSVの空欄で表し、JSONでは `null` を使います。

診断処理で計算した風速・角度差・評価可否などの列が追加されることがあります。読み込み側は、知らない列が増えても、必要な列を名前で選んで扱う設計にします。

## `metadata.json`

スキーマの版は `schema_version`、時刻の基準は `timezone` で識別します。初版はそれぞれ `1.0.0`、`Asia/Tokyo` です。実際の出力には次の情報を記録します。

- 使ったモードと、合成・実観測・数値予報の別。
- 地点名、指定した緯度・経度、APIが返した格子の座標、分かる場合は観測所の情報。
- 学習・調整・最終評価の期間、予測時間先、入力項目、候補と選んだモデル、乱数の種。
- 予測起点が観測の入力基準、API取得時刻、モデル初期時刻のいずれか。
- 出典URL、取得時刻、モデル名、モデル初期時刻、入手可能時刻を確認できたか。
- Pythonとライブラリ、コードの版。

取得した日時とモデル初期時刻を同じ項目で上書きしません。実際の入手可能時刻が分からないときは、その不明な状態を残します。合成データには仮想観測点であることを記録します。

## 誤差表と改善度

`summary.csv` の主な指標は次のとおりです。

| 列 | 意味 |
| --- | --- |
| `speed_mae_ms` | 風速の平均絶対誤差 |
| `speed_rmse_ms` | 風速の二乗平均平方根誤差 |
| `speed_bias_ms` | 風速の「予測−観測」の平均 |
| `direction_mae_deg` | 円周上の角度差の平均 |
| `within_45_pct` | 風向誤差が45°以内の割合 |
| `vector_rmse_ms` | 風の成分を合わせたRMSE |
| `n_speed`, `n_direction`, `n_vector` | それぞれの指標の評価件数 |
| `n_excluded` | 除外理由がある行の件数 |
| `n_calm` | 静穏として方向評価から外した件数 |
| `n_undefined_direction` | 観測に風があるが、予測の向きが定まらなかった件数 |

`skill.csv` では、比較するモデルと持続予報で両方とも風速を採点できる行だけを使います。`speed_skill_pct` が改善度、`ci_low_pct` と `ci_high_pct` が日単位ブートストラップによる95%区間です。`n_pairs` と `n_days` は、その計算に使った組と日の数です。定義と解釈は[解析方法](forecast-method.md)を参照してください。

`observations.csv` の `source_kind` は、合成データか実観測かを表します。単独のCSVを読み戻す場合もこの区分を保持し、区分の異なる入力は同じ学習データへ混ぜません。

## 保存データを引き継ぐとき

同じ観測所の年別CSVをまとめるときは、観測時刻でそろえます。予報の履歴は、対象時刻だけで重複を消さないようにします。同じ対象時刻でも、取得したときやモデル初期時刻が異なる予報は、別の予報だからです。

観測履歴を含むZIPは、Colabの「CSV・保存データを選ぶ」でそのまま再利用できます。予報履歴を含むZIPを選んで最新・過去予報を取得すると、保存した予報も引き継ぎます。地点の異なる履歴は混ぜません。数値予報の `model` は格子の選択を区別するため `jma_msm:land` のように保存し、元のモデル名は `weather_model` に残します。これは独立した別モデルという意味ではありません。

Web側では、この形式を読み込んで地図・表・グラフを表示する予定です。誤差の計算方法はColab側と共通にし、Web側で独自の定義に置き換えない方針です。
