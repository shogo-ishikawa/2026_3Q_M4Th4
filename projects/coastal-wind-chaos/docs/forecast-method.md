# 海岸の風速・風向予報ラボ：解析方法

このラボの問いは「選んだ地点で、与えた情報から何時間先の風をどの程度予測できるか」です。既存の気象予報を比較する実験と、観測データからモデルを学習する実験を区別します。

## 予測する地点と量

気象モデルの10m風予報と、観測所の風向・風速を扱います。観測所の位置や風速計の高さは、モデルの格子や高さと完全に一致するとは限りません。観測所の移転・測器の変更も、解析期間を選ぶときに確認します。

沿岸の例示地点では既存予報を比較し、観測による評価は銚子・稚内などの観測所ごとに行います。近隣観測所の観測を海岸の実測に置き換える処理は行いません。

風向は「どちらから吹くか」を北0°・東90°として表します。学習では風向の角度をそのまま回帰せず、東向き成分 `u` と北向き成分 `v` を使います。

\[
u=-s\sin\theta,\qquad v=-s\cos\theta
\]

ここで `s` は風速です。予測した成分から風速と風向へ戻すため、359°と1°を離れた数として扱う問題を避けられます。

## 時刻を区別する

| 時刻 | 意味 |
| --- | --- |
| 入力観測時刻 | 予測に使った最新の観測が表す時刻 |
| 予測起点 `issue_time` | 観測からの学習では入力の基準時刻。既存予報では、取得基準かモデル初期時刻かを記録する |
| 対象時刻 `target_time` | 予測する風が表す時刻 |
| モデル初期時刻 | 数値予報計算の出発点となる時刻 |
| 取得時刻 | ColabがAPIからデータを受け取った時刻 |

モデル初期時刻と、その予報が実際に利用可能になった時刻は違います。初期時刻から3時間先の評価と、利用者が予報を入手してから3時間先の評価を混同しません。入手可能時刻を確認できない過去予報は、モデル初期時刻を基準とする評価として説明します。

機械学習の時刻と出力CSVは日本標準時（JST、`Asia/Tokyo`）を基準にします。APIのUTC時刻はJSTへ変換して観測と照合します。内部の日時はタイムゾーンを付けないJSTなので、別のソフトでUTCと解釈しないよう、出力のメタデータにもタイムゾーンを記録します。

## 観測から学習データを作る

気象庁の時別値CSVを読み込み、品質情報で使用する値を選びます。標準は正常値を使います。欠けた時刻は時系列の中に残し、未来の値で埋め戻すことはしません。

1行を予測起点 `t` とし、`t+h` の風の成分を答えにします。入力には次の情報を使います。

| 入力の組 | 内容 |
| --- | --- |
| 季節・時刻 | 対象時刻の時刻・季節を周期関数で表した値、学習期間だけで計算した月×時刻の平均風 |
| 直近の風 | 0・1・2・3・6・12・24時間前の `u, v`、直近24時間の平均、直近1・3時間の変化 |
| 任意の気象項目 | 気温・気圧・日照の現在までの値や変化。学習期間の利用状況から使える列を決める |

対象時刻の暦は予測時点で分かる情報です。一方、対象時刻の実際の気温や気圧は入力しません。標準化、平均風、入力列の選択も、評価期間の答えを使わずに決めます。

初版の観測モデルは1地点ずつ学習します。気象予報や近隣地点の値を学習への入力として加える実験は、観測だけの基準と比較する次の課題です。

## 学習・調整・最終評価

標準は3年を時間順に分け、最初の1年を学習、次の1年を調整、最後の1年を最終評価に使います。日付を指定した分割も可能です。

予測する時間先ごとに、線形モデル（リッジ回帰）と勾配ブースティングなどの候補を調整期間の風速MAEで比べます。最終評価の結果を見て候補を選び直すことはしません。選択後は、最終評価より前の学習・調整データを合わせて学習し直します。

学習行の対象時刻が次の期間へ入り込む場合は、その行を学習から外します。例えば学習終了の1時間前を起点とする3時間先の答えは、次の期間にあるため使いません。

手法や予測時間の比較には、同じ地点・予測起点・対象時刻の組をそろえます。欠測で使える行が異なる場合は、共通に採点できる行と除外数を明示します。

## 比較する予測

| 手法 | 考え方 |
| --- | --- |
| 持続予報 | 起点の風がそのまま続く |
| 24時間周期の持続予報 | 対象時刻と同じ時刻帯の、起点以前の風を使う |
| 気候値予報 | 学習期間の月×時刻ごとの平均風を使う |
| 線形モデル | 入力と将来の風の成分を線形の関係で結び付ける |
| 勾配ブースティング | 複数の小さな決定木で、入力と答えの関係を学習する |

1・3・6・12・24時間先を標準とし、36・48・72時間先も調べられます。時間先ごとに直接予測するため、観測していない未来の実測を次の入力に使うことはありません。

## 既存の気象予報を検証する

最新予報は取得した時点の予報として保存します。単に「現在の風」を表示するAPIの値も、モデル由来なら観測値とは別に扱います。

過去の短時間先の予報を検証する場合は、Open-MeteoのSingle Runs APIで初期時刻を指定します。一般のHistorical Forecast APIは複数の計算回の冒頭をつないだ系列なので、そのまま「3時間先の予報」としては採点しません。

保存されている期間はモデルとAPIによって異なります。Single Runs APIでは多くのモデルが2026年4月2日以降、ECMWF IFS HRESは2024年3月以降です。観測だけの機械学習を数年分で試す実験と、同じ年数の既存予報を比較できるとは限りません。実際に取得できた共通期間を使います。

MSMの予報期間は計算回によって39時間または78時間です。長い予測先を選んでも、モデルや計算回にない値を作り足しません。また、APIが1時間間隔で返す値でも、元の予報がより粗い時間間隔の場合は補間を含みます。

## 誤差の定義

風速の誤差を `予測−観測` とします。風速MAEは誤差の絶対値の平均、RMSEは誤差の2乗平均の平方根です。偏りは符号を保った誤差の平均なので、正なら強く、負なら弱く予測する傾向を表します。ベクトルRMSEは `u, v` の誤差の2乗和を平均して平方根を取ります。

風向の誤差は、円周上の短い側の角度差（0〜180°）です。観測が静穏（風速0.2m/s以下）の場合は風向の採点から外し、件数を記録します。風がある観測に対して予測の風向が未定義の場合は、既存教材と同じく角度誤差90°として数え、45°以内には数えません。90°は一様なランダム方向の平均角度誤差を基準にした取り決めで、物理的な誤差の上限ではありません。

未来の予測は、観測がまだないため採点しません。観測や予測が欠けた行、入力不足で除外した行も数値を0として採点しません。評価件数を指標ごとに残します。

### 基準からの改善度

同じ行で採点した持続予報のMAEを `E_base`、比較するモデルのMAEを `E_model` として、次を計算します。

\[
\mathrm{改善度}(\%)=100\left(1-\frac{E_\mathrm{model}}{E_\mathrm{base}}\right)
\]

正なら改善、負なら悪化です。持続予報のMAEが0の場合は割合を定義できないため空欄とします。

連続する時刻の誤差は独立とは限りません。95%区間は日単位のまとまりを保ったペア付きブートストラップで求めます。予測起点が同じ日の行をモデルと持続予報の両方から取り直し、改善度を計算し直します。評価日が1日だけの場合は95%区間を計算しません。これは改善度の推定のばらつきであり、将来の風速の予測区間ではありません。

## 調べられることと、その先

月・時刻・風向・風速帯別の誤差を比べると、平均値だけでは見えない条件依存性を調べられます。例えば「日中の南寄りの風では改善するが、強い北風では改善しない」といった結果から、入力や地形との関係を考えるきっかけが得られます。区分ごとの件数が少ない場合は結論を急がず、別の期間でも確かめます。

ここで分かるのは、選んだ情報・モデル・期間における予測性能です。誤差の増加だけから、カオスによる物理的な予測限界を特定することはできません。ローレンツ系によるカオスの実験は、既存の発展教材で別に扱います。
