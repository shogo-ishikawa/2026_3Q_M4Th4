# データ

このフォルダには、プログラムが作る合成データと、自分でダウンロードした気象庁のデータを置きます。CSVファイルと `raw/` フォルダはGitで管理しません（作品の `.gitignore` で除外しています）。

| ファイル・フォルダ | 内容 | 作り方 |
| --- | --- | --- |
| `sample_coastal_amedas.csv` | 合成データ（気象庁のダウンロードファイルと同じ形式） | `python scripts/generate_sample_jma_csv.py` |
| `sample_coastal_truth.csv` | 合成データの「真の状態」と成分の内訳（教材用） | 上のコマンドに `--truth-output data/sample_coastal_truth.csv` を付ける |
| `raw/` | 自分でダウンロードした気象庁のCSV | 手作業でダウンロードして置く |

## 1．合成データ

### 1.1　何を表しているか

南側に海、北側に陸がある**仮想観測点**の、1時間ごとの気温・風向・風速・日照時間・海面気圧です。**気象庁の観測値ではありません。** 地点名は「仮想海辺観測点（合成）」で、ファイルの1行目にも合成データであることを書いています。

既定では、2023年1月1日1時から2026年1月1日0時（2025年12月31日24時）までの3年分、26,304時間を作ります。2024年2月29日も含みます。同じ環境（Python と NumPy などの版）で乱数の種（`seed`、既定2026）が同じなら、同じファイルになります。版が違うと、乱数の並びが変わる可能性があります。

時刻は日本標準時（JST）です。気象庁の時別値と同じく、各行の時刻はその1時間の終わりを表します。

| 値 | 時刻 t の行が表すもの |
| --- | --- |
| 気温・海面気圧 | 時刻 t の値 |
| 風向・風速 | 時刻 t の直前10分間の平均（を想定） |
| 日照時間 | t の1時間前から t までの合計 |

### 1.2　作り方の考え方

風は、東向きの成分 u と北向きの成分 v で作り、次の成分を**成分ごとに足し合わせます**。風向の角度どうしは足しません。角度を足すと、0°と360°の境目で意味のない値になるためです。

| 成分 | 内容 | 主な設定 |
| --- | --- | --- |
| 周期成分 | 季節風（冬は北西寄り、夏は南東寄り）、海風・陸風（日中は南寄り、夜は北寄り。時刻とともに時計回りに向きを変える）、気温・気圧の年変化と日変化、雲量の季節変化 | `use_periodic`, `breeze_strength`, `monsoon_strength` |
| 背景成分 | 数日かけてゆっくり変わる確率的な変動。AR(1)過程を24時間の移動平均で滑らかにしたもの | `use_background`, `background_strength`, `background_days` |
| 不規則成分 | 1時間前の状態と相関する確率的な変動。安定な AR(1)過程（`ar_phi` は −1 より大きく 1 より小さい） | `use_ar`, `ar_strength`, `ar_phi` |
| 前線通過 | 平均6日間隔のランダムな時刻に来る急変。通過前（既定12時間）に南西寄りの風が強まり、気圧が下がる。通過時に北西の風へ急に変わり、気温が下がる | `use_fronts`, `front_strength`, `front_interval_days`, `front_precursor_hours` |
| 観測 | u, v への観測誤差（標準偏差0.3 m/s）、風速0.1 m/s 単位・16方位への丸め、0.2 m/s 以下は「静穏」、まれな欠測 | `observation_noise_ms`, `missing_rate` |

成分ごとに別の乱数の種を使うので、ある成分を止めたり強さを変えたりしても、ほかの成分は同じ値のままです。そのため、成分の違いだけを比べられます。

この仮想地点で海風が南から吹くのは、海を南に置いた設定のためです。実際の海岸では、海の向きや地形によって海風・陸風の向きは変わります。

これは簡単な式と乱数を組み合わせた**現象のモデル**で、大気の流れを物理法則に従って計算する数値予報ではありません。前線は外から決まるランダムな時刻に来るので、予兆（`front_precursor_hours`）を0にすると、その地点の過去の観測だけから到来を当てることはできません。降水量や湿度は作りません。

### 1.3　プリセット

| 名前 | 内容 |
| --- | --- |
| `default` | すべての成分 |
| `periodic_only` | 周期成分のみ（背景成分・不規則成分・前線なし。観測誤差と丸めは残る） |
| `periodic_ar` | 周期成分＋不規則成分（AR変動） |
| `no_precursor` | すべての成分。ただし前線の予兆なし |

```bash
python scripts/generate_sample_jma_csv.py --preset periodic_only --output data/periodic_only.csv
python scripts/generate_sample_jma_csv.py --set ar_strength=2.0 --set front_precursor_hours=0
```

すべての設定の名前と既定値は `src/coastal_wind_chaos/sample_data.py` の `DEFAULT_SETTINGS` にあります。

### 1.4　ファイルの形式

気象庁「過去の気象データ・ダウンロード」の時別値CSV（「すべて数値で格納」「日付リテラルで格納」）と同じ構造です。文字コードは Shift_JIS（cp932）、改行は CRLF です。

```text
合成データ（気象庁の観測値ではありません）：coastal_wind_chaos で生成、プリセット default、seed=2026
（空行）
,仮想海辺観測点（合成）,仮想海辺観測点（合成）,…
年月日時,気温(℃),気温(℃),気温(℃),日照時間(時間),日照時間(時間),日照時間(時間),日照時間(時間),風速(m/s),風速(m/s),風速(m/s),風速(m/s),風速(m/s),海面気圧(hPa),海面気圧(hPa),海面気圧(hPa)
,,,,,,,,,,風向,風向,,,,
,,品質情報,均質番号,,現象なし情報,品質情報,均質番号,,品質情報,,品質情報,均質番号,,品質情報,均質番号
2023/1/1 1:00:00,6.8,8,1,0,1,8,1,3.1,8,北北西,8,1,1020.3,8,1
```

- 1行目は、本物のファイルでは「ダウンロードした時刻：…」です。
- 真夜中（24時）は、翌日の `00:00:00` と書きます（例：`2026/1/1 00:00:00`）。
- 太陽が出ていない1時間の日照時間は `0`、現象なし情報は `1` です。日照がありうる時間に日照がなければ `0.0` です。
- 欠測の時刻は、値と現象なし情報が空欄で、品質情報が `1` です（気象庁のファイルと同じ書き方）。

### 1.5　真の状態のファイル（教材用）

`--truth-output` で保存するファイル（UTF-8）には、観測誤差と丸めを含まない真の値と、成分の内訳が入っています。

| 列 | 内容 |
| --- | --- |
| `u_true`, `v_true`, `speed_true`, `direction_true_deg` | 真の風（成分、風速、風向） |
| `u_periodic`, `u_background`, `u_ar`, `u_front`（v も同様） | 各成分 |
| `temperature_true`, `pressure_true`, `sunshine_true_h`, `daylight_fraction` | 気温・気圧・日照時間と、その1時間に太陽が出ていた割合 |
| `hours_since_front` | 直前の前線通過からの時間（通過した時刻は0） |

このファイルは、観測誤差の大きさや、前線の前後の誤差を調べるためだけに使います。予測の入力には使いません。実際の観測には「真の状態」はありません。

## 2．実データ：気象庁「過去の気象データ・ダウンロード」

### 2.1　ダウンロードの手順

自動でダウンロードするプログラムは用意していません。気象庁は、自動化ツールによる過度のアクセスを控えるよう求めています。次の手順で、ブラウザから手作業でダウンロードしてください（2026年10月時点の画面の表記です。画面は変わることがあります）。

1. [過去の気象データ・ダウンロード](https://www.data.jma.go.jp/risk/obsdl/index.php)を開きます。
2. 「地点を選ぶ」で、**風向・風速を観測している地点**を1つ選びます。現地気圧・海面気圧は気象台など（官署）だけで観測しています。アメダスの多くの地点では、降水量・気温・風向・風速・湿度を観測し、日照時間は推計値です。
3. 「項目を選ぶ」で「時別値」を選び、「気温」「風向・風速」「日照時間」を選びます。気象台などなら「海面気圧」も選べます。
4. 「期間を選ぶ」で2〜3年を選びます。一度にダウンロードできるデータ量には上限があります（画面右上の棒グラフ）。上限を超えるときは、1年ずつに分けてダウンロードします。
5. 「表示オプションを選ぶ」は既定のままにします。
   - 利用上注意が必要なデータ：値を格納し、注意が必要なことを示す情報をつける（これで「品質情報」の列が入ります）
   - 観測環境などの変化の前後で不均質となったデータ：すべての期間の値を格納し、不均質を示す情報をつける（これで「均質番号」の列が入ります）
   - ダウンロードCSVファイルのデータ仕様：「すべて数値で格納」、日付の形式は「日付リテラルで格納」（「年月日などに分けて格納」も読み込めます）
   - 「都道府県名を格納」を選んでも読み込めます（地点名の行の上に1行増えます）。
6. 「CSVファイルをダウンロード」を押し、ファイル（`data.csv`）を `data/raw/` に分かりやすい名前で保存します。**ダウンロードした日**を記録しておきます（ファイルの1行目にも書かれています。`run_experiments.py` はこの行を `results/run_info.json` に記録します）。
   地点名・観測所の種類・風速計の高さなども記録しておくと、結果を説明するときに役立ちます。CSVにはこれらは入っていません。アメダスの観測所の情報（緯度・経度・高さ、風速計の高さ、観測の開始日・終了日など）は、気象庁の[アメダス観測所の一覧（CSV形式のテキスト、Shift_JIS）](https://www.data.jma.go.jp/stats/data/mdrr/chiten/meta/amdmaster.index4)で確かめられます。
7. 読み込みます。1年ずつのファイルは、一覧で渡すとつながります。

```python
from coastal_wind_chaos import wind_pipeline as wp

weather = wp.load_weather(["data/raw/station_2023.csv", "data/raw/station_2024.csv"])
wp.summarise_weather(weather)
```

コマンドラインでは `python scripts/run_experiments.py --data data/raw/station_2023.csv data/raw/station_2024.csv --skip-scenarios` で同じ実験ができます。

「数値以外の記号を含む」形式（表示用の記号つき）のCSVは読み込めません。そのときは「すべて数値で格納」でダウンロードし直すよう、エラーで知らせます。複数の地点を1つのファイルにまとめたCSVも読み込めないので、1地点ずつダウンロードしてください。

「利用上注意が必要なデータの扱い」で「値を表示(格納)しない」を選ぶと、品質情報の列がないファイルになります。読み込むことはできますが、欠測や疑問値を区別できず、アメダスでは夜の日照時間（空欄）と欠測も区別できません。`summarise_weather` は「品質情報の列：なし」と表示します。上の手順5の設定でダウンロードし直すことを勧めます。

### 2.2　CSVの構造と、このプログラムでの扱い

1行目がダウンロードした時刻、2行目が空行、3行目が地点名、4行目が要素名です。「風向・風速」を選ぶと、5行目に「風向」の補助見出しが入り、その下の行に「品質情報」「均質番号」「現象なし情報」が入ります。`read_jma_csv` は、「年月日時」の行を探し、その下の見出しを組み合わせて列名を作ります。

| CSVの要素名 | 列名 |
| --- | --- |
| 気温(℃) | `temperature_c` |
| 風速(m/s) | `wind_speed_ms` |
| 風向（風速の下の補助見出し） | `wind_direction`（文字のまま）、`wind_direction_deg`（度） |
| 日照時間(時間) | `sunshine_h` |
| 海面気圧(hPa)・現地気圧(hPa) | `sea_level_pressure_hpa`, `station_pressure_hpa` |
| 降水量(mm)・相対湿度(％) | `precipitation_mm`, `relative_humidity_pct` |
| 品質情報・均質番号・現象なし情報 | 列名の後ろに `_quality`, `_homogeneity`, `_no_phenomenon` |

**時刻**　日本標準時（日本中央標準時、24時制）です。風向・風速は観測時刻の前10分間の平均、日照時間と降水量は前1時間の合計、気温と気圧はその時刻の値です。日付を1列にした形式では24時が翌日の `00:00:00`、年・月・日・時を分けた形式では同じ日の `24` 時と書かれます。どちらも同じ日時として読み込みます。

**品質情報**　気象庁のヘルプによる意味と、このプログラムでの既定の扱いです（`min_quality` で変えられます）。

| 値 | 意味 | 既定の扱い |
| --- | --- | --- |
| 8 | 正常値 | 使う |
| 5 | 準正常値（統計のもとの資料が許容範囲で欠けている） | 使う |
| 4 | 資料不足値（許容範囲を超えて欠けている） | 欠損にする |
| 2 | 疑問値 | 欠損にする |
| 1 | 欠測 | 欠損にする |
| 0 | 観測・統計項目ではない（その地点では観測していない） | 欠損にする |

**現象なし情報**　気象台などの日照時間・降水量に付きます。`1`（現象なし）の行は値が `0` と書かれます。欠測などの行では空欄です。アメダスの地点では現象なし情報の列がなく、夜の日照時間が空欄で品質情報が正常（8）になっていました。どちらも「その1時間に日照（降水）がなかった」として0にそろえます。後者は2026年10月に実際にダウンロードしたファイルで確かめた扱いで、気象庁のヘルプには書かれていません。念のため、`summarise_weather` は空欄を0とした時刻の数と、そのうち必ず日中になる10〜14時の数を表示します。10〜14時の数が0でなければ、元のCSVを確かめてください。

**静穏**　平均風速が0.2 m/s 以下のときは、風向が「静穏」になります（気象庁「過去の気象データ検索」の「[要素ごとの値の補足説明](https://www.data.jma.go.jp/stats/data/mdrr/man/sampling.html)」）。静穏は風向が決まらないので `wind_direction_deg` を欠損にし、u = v = 0 とします。風向の評価からは除きます（`summarise_weather` で件数を確かめられます）。

**均質番号**　観測場所の移転や測器の変更などで、その前後の値を単純に比べられないことを示します。番号は要素ごと（気温、風など）に付き、番号そのものに意味はなく、ダウンロードしたファイルごとに1から付きます。`summarise_weather` は番号が変わった時刻を表示します（複数のファイルをつないだときは、ファイルの境目でも変わることがあります）。学習期間とテスト期間の間で観測環境が変わると、結果に影響することがあります。気象庁は、観測環境の変化による統計の切れ目を[統計切断情報（CSV）](https://www.data.jma.go.jp/stats/data/mdrr/chiten/meta/discnt_sfc.csv)として公開しています。

**そのほかの注意**

- 気象庁のデータは、品質管理などによって後から修正されることがあります。ダウンロードした日を記録し、結果と一緒に残してください。
- アメダスの日照時間は、2021年3月2日から、気象衛星のデータを用いた推計値です。それ以前の値や気象台などの値とは単純に比較できません。
- アメダスの風速は、地点ごとの観測方法の変更日（2008年以降）までは1 m/s 単位でした。
- 風向風速計の高さや、周りの建物・地形によって、同じ地域でも風は変わります。
