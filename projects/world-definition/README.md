# WORLD DEFINITION

**世界のルールを変えて、進める道を作るパズルゲームです。** 水を凍らせる、石を浮かせる、木の光を運ぶ。物体と動作を組み合わせて全5ステージのゴールを目指します。公開版のバージョンは **v1.1.1** です。

2026年度「計算科学基礎」の学生制作をもとにしています。C++・raylibの試作とJavaScript・Canvas版にあった「世界に働きかけて道を作る」という発想を引き継ぎました。v1.1.0では定義による形・動き・光の変化を見やすくし、物体を運んで光や脈動を届けるステージを追加しています。v1.1.1ではステージ2のゲート周辺を修正し、状況に合った攻略ヒントと、安全な岸から再開できる仕組みを加えました。

## すぐに遊ぶ

GitHub Pagesの作品ページ、またはダウンロードしたフォルダの **`index.html`** をブラウザで開きます。標準モードにはインストール、ログイン、APIキー、AIモデルの準備は必要ありません。ダウンロード後はオフラインでも遊べます。

1. 最初の説明を読み、遊び始めます。
2. WASDまたは矢印キーで移動します。スマートフォンでは画面の方向ボタンを使います。
3. 研究室で物体と動作を選び、「ルールを適用」を押します。選択しただけでは世界は変わりません。
4. 変化を確かめながら青い結晶を拾い、ゲートを開いてゴールへ進みます。
5. クリアすると次のステージが解放されます。ステージ選択から解放済みの場所へ戻ることもできます。

詳しい手順と段階的なヒントは **[遊び方ガイド](guide.html)** にまとめています。ステージ別の攻略例は折り畳みを開いたときだけ表示します。

## 操作

| キー・ボタン | 動作 |
| --- | --- |
| WASD / 矢印 | プレイヤーの移動 |
| E＋移動 | 近くにある浮遊中の石・木を運ぶ |
| E長押し | 「炎＋加熱」を適用した後、ゲートの近くで立ち止まって加熱する |
| L | ルール研究室にフォーカスを移す |
| H | 操作説明を開く |
| J / 攻略ヒント | 現在の状況に合った攻略ヒントを開閉する |
| R | 確認してから現在のステージをやり直す |
| Tab / Shift＋Tab | ボタンなどの選択を順に移す |
| Escape | 開いている説明を閉じる |
| ステージ選択 | 解放済みのステージを選んで遊ぶ |

画面の「操作」ボタンはEキーと同じ働きです。浮遊物体を運ぶときは方向ボタンと同時に押してください。複数の浮遊物体が近くにある場合は、研究室で選んだ石・木を優先します。選んだ物体が近くにない場合は、近い浮遊物体を運びます。

## 困ったら攻略ヒントを開く

ゲーム画面の下にある **「攻略ヒント J」**、またはJキーで開閉できます。まず考え方を読み、必要に応じて「もっと具体的に」「答えの手順を見る」で詳しくします。前の段階にも戻れます。川を渡る、受信盤を点灯させる、ゲートを開くなど、進行に合わせてヒントが切り替わります。

「次に向かう場所を表示」にチェックすると、ゲーム画面に目印が出ます。近くの物体やゲートで使えるE操作は、画面の案内も確認してください。操作方法だけを読みたい場合はHキー、ステージ全体の攻略例は[遊び方ガイド](guide.html#stages)を使えます。

川の手前で配置に困ったときは、ヒント内の「運んだ物体の配置だけやり直す」を開き、石・木の配置を戻せます。定義、結晶、点灯した盤は残ります。橋が消えて先へ進めなくなるのを防ぐため、川の上や向こう岸からは使えません。

## 定義すると、何が変わるか

動作は物体ごとに最大3つまで組み合わせられます。対象に適用中の効果はバッジでも確認できます。

| 動作 | 見える変化・できること |
| --- | --- |
| 凍結 | 水面が氷になり、川を歩けます。炎に使うと消火されて安全に近づけます。 |
| 固体化 | 水面が石張りの通路へ変わります。 |
| 浮遊 | 石・木が地面から浮き、影と浮遊の表示が現れます。E＋移動で運び、川では足場として使えます。炎は上へ浮きます。 |
| 成長 | 石・木や炎が大きくなります。足場の幅と長さも広がるため、広い川で役立ちます。 |
| 発光 | 対象が光源になります。光の紋章へ物体を運び、発光させる仕掛けもあります。 |
| 脈動 | 光が周期的に変化し、波紋が広がります。共鳴盤へ光と脈動を届けると作動します。 |
| 移動 | 炎が左右に往復します。移動の軌跡も表示されます。 |
| 加熱 | 炎が熱を帯びます。ゲートの近くでEを長押しすると加熱が進み、ゲートが開きます。結晶取得後に使えます。 |

| 物体 | 基本の動作 |
| --- | --- |
| 水 | 凍結、固体化、発光、脈動 |
| 石・木 | 浮遊、成長、発光、脈動 |
| 炎 | 浮遊、移動、成長、発光、凍結、脈動、加熱 |

ステージ2以降は水の凍結と固体化が封印されています。選べる動作と画面の目標を確認し、石や木を使って進みましょう。

ルールは物体ごとに残ります。水のルールを作った後で炎のルールを変えても、水のルールは残ります。同じ物体への再適用は置き換えです。川の途中で足場を失う変更は受け付けないため、いったん岸へ戻ってから変更してください。

## 5つのステージ

| ステージ | 主な仕掛け |
| --- | --- |
| 1：封印されたゴール | 水を変える方法と浮遊物体を橋にする方法を試せます。結晶で加熱を解放する基本のステージです。 |
| 2：石の渡し場 | 水の定義が封印された川を、石や木の足場で渡ります。 |
| 3：光を運ぶ庭 | 木を光の紋章へ運び、発光させて封印を解きます。 |
| 4：脈動の回廊 | 石を共鳴盤へ運び、発光と脈動を組み合わせて作動させます。 |
| 5：最後の定義 | 広い川と2つの受信盤が登場します。石の成長と木の発光・脈動を使い分けます。 |

受信盤は指定された物体を近くへ運び、必要な動作を約1秒間届けると点灯します。一度点灯した盤は、その後も点灯したままです。受信盤があるステージでは全ての盤の点灯と結晶の回収を済ませてからゲートを加熱します。

各ステージには金の欠片が2個あります。収集は追加の目標で、クリアの必須条件ではありません。まずゴールを目指し、慣れたら欠片を探したり少ない定義回数で解いたりしてみてください。

## 進行の保存

ステージの解放状況とクリア記録は、利用中のブラウザに保存します。ステージ選択から解放済みの場所へ再挑戦できます。記録には定義回数、集めた欠片、クリア時間が含まれます。

炎に触れたときは、このプレイ中に最後に立っていた安全な岸へ戻ります。そこが物体で塞がっている場合は、近くの安全な場所へ戻ります。ルール、回収済みの結晶や欠片、点灯した受信盤は残るため、橋を運び直さずに続けられます。

プレイヤーの位置や途中のルール、この復帰地点はブラウザに保存しません。再読み込み後はステージを選んで最初から遊びます。別の端末やブラウザとは共有されず、ブラウザのサイトデータを消すと記録も消えます。保存を利用できない環境でも、そのまま遊べます。

## 任意のローカルAI連携

標準モードでは名前と説明もブラウザ内で組み立てます。ローカルAIを使う場合はOllamaが**ルールの名前と説明**を補助します。実際の効果はゲーム側で定めた処理です。自由な文章から新しいゲーム処理を生成する機能はありません。

1. [Ollama](https://ollama.com/)を導入し、起動します。
2. ターミナルでモデルを取得します。モデル本体は同梱していません。

   ```sh
   ollama pull qwen3.5:4b
   ```

3. この作品フォルダでローカルサーバーを起動します。

   ```sh
   # macOS / Linux
   python3 server.py --port 8765
   # Windows
   py -3 server.py --port 8765
   ```

4. `http://127.0.0.1:8765/` を開き、ローカルAIの選択肢を有効にします。

別の導入済みモデルを使う場合は環境変数 `WORLD_DEFINITION_MODEL` を設定してから起動してください。終了はターミナルでCtrl＋Cです。サーバーは同じコンピューターからだけ接続できる設定です。GitHub PagesではローカルAI連携を使いません。実モデルによる生成と各OSでの実機動作は未検証です。

## コードを読む・変えてみる

| ファイル | 内容 |
| --- | --- |
| `index.html` / `style.css` | 画面の構造と見た目 |
| `engine.js` | ステージのデータ、世界の状態、ルール、移動と当たり判定 |
| `progress.js` | この端末の解放状況とベスト記録 |
| `renderer.js` | 物体や効果、ステージの描画 |
| `app.js` | 入力、画面更新、ステージの選択と進行 |
| `server.py` | 任意のローカルAI連携 |
| `tests/` | ステージの攻略、入力、ローカルサーバーなどの確認 |
| [docs/design.md](docs/design.md) | 処理の流れと変更して試す課題 |
| [native-reference/](native-reference/) | 元のC++版の参照用ソースと素材の利用条件 |

開発時の確認コマンドです。ローカルAIのテストは応答を模擬するため、モデルの導入なしで実行できます。

```sh
node tests/engine.test.js
node tests/app-input.test.js
node tests/progress.test.js
python3 -m unittest discover -s tests -p 'test_*.py'
```

ゲーム進行のテストは全5ステージでゲートの中央を通り、炎に触れずにゴールまで進めることを確認します。受信盤の条件、足場の保持、炎に触れた後の安全な岸への復帰も扱います。入力のテストはキーボード、画面ボタン、ダイアログ、リセット時の応答を扱います。表示の分かりやすさは実際のブラウザでも確認してください。実OllamaとC++参照版のビルドは未確認です。

## 公開用ファイルの作成

リポジトリのルートで `python3 scripts/build_public_site.py` を実行すると、`_site/world-definition/` に公開用ファイルと配布ZIPが作られます。ZIPを解凍すると `v1.1.1/` になり、`index.html` を開いて遊べます。ソースはこの `projects/world-definition/` で管理します。

GitHub Pagesの初回設定は **Settings → Pages → Build and deployment → Source → GitHub Actions** です。その後はmainへの更新時に確認と配信を行います。Actionsの **Check and publish public works → Run workflow** からも再実行できます。
