# WORLD DEFINITION

**定義を変え、手掛かりをつなげて遺跡を解く探索パズルです。** 水を凍らせれば道になりますが、水車は止まります。石を浮かせれば運べますが、床の重さの仕掛けは押せません。便利な性質をいつ使い、いつ元へ戻すかを考えて進みましょう。公開版は **v1.3.0** です。

広いマップを探索する**謎解き編4面**を、最初から遊べます。以前の9面は操作や動作を試せる練習ステージとして残しています。2026年度「計算科学基礎」の学生制作にあった「物体の性質を変えて道を作る」という発想を引き継ぎ、変化を組み合わせる順番と、定義を解除する意味を加えました。

## すぐに遊ぶ

GitHub Pagesの作品ページ、または配布ZIPを解凍したフォルダの **`index.html`** を開きます。標準モードにはインストール、ログイン、APIキー、AIモデルの準備は必要ありません。ダウンロード後はオフラインでも遊べます。

1. 最初の画面から謎解き編を始めます。途中保存があれば「続きから」を選べます。
2. WASD・矢印キーで歩き、看板や石碑、レバーに近づいてEを押します。
3. 研究室で物体と動作を選び、「ルールを適用」を押します。仕掛けや水の流れがどう変わったか確かめます。
4. 性質を元へ戻したいときは、その物体を選び、「この物体の定義を解除」を押します。別の物体のルールは残ります。
5. 広い場所ではMキーで全体地図を開きます。読んだ手掛かりは「手掛かり手帳」で確かめられます。
6. 次の進み方に迷ったらJキーで攻略ヒントを開きます。必要なときだけ具体的な手順へ進めます。

画面の操作ボタンも使えます。詳しい手順と、必要なときだけ開ける攻略例は **[遊び方ガイド](guide.html)** にまとめています。

## 操作

| キー・ボタン | 動作 |
| --- | --- |
| WASD / 矢印 | プレイヤーの移動 |
| E | 近くの看板・石碑を調べる、レバーや紋章を操作する |
| E＋移動 | 近くにある浮遊中の石・木を運ぶ |
| この物体の定義を解除 | 選んだ物体を元の性質へ戻す |
| M / 全体地図 | 全体地図と、プレイヤーを追う表示を切り替える |
| L | ルール研究室へフォーカスを移す |
| H | 操作説明を開く |
| J / 攻略ヒント | 現在の状況に合ったヒントを開閉する |
| Z / 1手戻す | 直前の定義・解除・運搬・Eでの調査や装置操作などを変更前へ戻す |
| R | 確認してから現在のステージをやり直す |
| Tab / Shift＋Tab | ボタンなどの選択を順に移す |
| Escape | 開いている説明を閉じる |
| ステージ選択 | 謎解き編の解放済みステージ、または練習ステージを選ぶ |

Eで調べるときは、方向キーを離して一度押してください。次の操作はEを離してから押し直します。浮遊物体を運ぶときはEと方向キーを同時に押します。石と木が両方とも近い場合は、研究室で選んだ浮遊物体を優先します。

練習の基本面では、「炎＋加熱」を適用した後、ゲートの近くで立ち止まってEを長押しすると加熱できます。

## 探索と謎解きの進め方

看板や石碑には、その場所の装置が何を必要としているかが書かれています。最初から正解の組み合わせを探すより、**変える前と変えた後を比べる**と手掛かりをつなげやすくなります。

- 通れた場所に仕掛けがあるなら、帰り道や出口まで同じ定義でよいかも確かめます。
- 水を固めて止まった装置があれば、水の流れが必要なのか考えます。
- 物体を運び終えたら、浮いている状態と地面に置いた状態の違いを見ます。
- 光で見つけた文字は手帳に残し、別の部屋でも読み返します。

全体地図では部屋と通路の位置を確かめられます。攻略ヒントも、最初は考え方だけを表示し、必要に応じて「もっと具体的に」「答えの手順を見る」と進められます。

## 定義を作る・解除する

物体ごとに最大3つの動作を組み合わせられます。対象と動作を選んだだけでは反映されないので、必ず「ルールを適用」を押します。同じ物体への再適用は、その物体のルールの置き換えです。

物体を元の性質へ戻すときは、研究室でその物体を選び、「この物体の定義を解除」を押します。水は流れ、浮いていた石や木は地面へ戻ります。別の対象に適用した定義は消えません。今いる足場を失う解除や、物体が壁に重なる変更は受け付けません。安全な場所へ移るか、Zで戻してから見直してください。

| 動作 | 見える変化・使い方 |
| --- | --- |
| 凍結 | 水を氷の通路に変えます。水の流れは止まります。炎に使うと消火できます。 |
| 固体化 | 水を硬い通路に変えます。水路の装置では、流れをせき止める性質も利用します。 |
| 浮遊 | 石・木が浮き、E＋移動で運べます。置く場所だけでなく、浮かせたままでよいかも考えます。 |
| 成長 | 石・木や炎が大きくなります。足場や、物体に反応する仕掛けにも影響します。 |
| 縮小 | 石・木と足場が小さくなります。狭い場所を通すときに使えます。 |
| 回転 | 石・木の足場を横向きにします。外すと縦向きへ戻ります。 |
| 発光 | 対象が光源になります。暗い場所の手掛かりや、光に反応する仕掛けを探せます。 |
| 脈動 | 光が周期的に変わります。練習面では共鳴盤への信号にも使えます。 |
| 移動 | 炎が左右に往復します。 |
| 加熱 | 炎が熱を帯びます。練習の基本面ではゲートを加熱するときに使います。 |

| 物体 | 対応する動作 |
| --- | --- |
| 水 | 凍結、固体化、発光、脈動 |
| 石・木 | 浮遊、成長、縮小、回転、発光、脈動 |
| 炎 | 浮遊、移動、成長、発光、凍結、脈動、加熱 |

成長と縮小、炎の凍結と加熱、水の凍結と固体化は同時に使えません。ステージによっては使える動作に制限があります。研究室の表示と、その場所の手掛かりを確認してください。

## 謎解き編と練習ステージ

謎解き編は広い場所を歩き、装置を動かす順番や、物体の役割が変わるタイミングを考える4面です。最初の面から始められ、クリアすると次の面へ進めます。各面の考え方と攻略例は[ガイド](guide.html#stages)にまとめています。

| 謎解き編 | 考えること |
| --- | --- |
| 1：止まった水車 | 渡るために水を止め、装置を動かすために流れを戻す |
| 2：光と影の書庫 | 光で詩を読み、消灯して通り、言葉を紋章の順へ読み替える |
| 3：重さが開く水門 | 石を運んで下ろす。重さと木の根を残して、水車へ水を返す |
| 4：水源の迷宮 | 堰で川床を出し、弁を組み替え、退路を作って流れを戻す |


以前の基本5面と応用4面は、ステージ選択から遊べる練習ステージです。水を変えて渡る、物体を運ぶ、縮小や回転を試す、複数の盤を点灯させるなど、一つの操作を確かめたいときに使えます。練習を全てクリアしてから謎解き編へ進む必要はありません。

## 試して戻す・続きから遊ぶ

「1手戻す」またはZキーで、直前の定義・解除、ひと続きの運搬、Eでの調査や装置操作を変更前へ戻せます。位置や途中の仕掛けもその時点へ戻るので、別の方法を試せます。戻せる履歴は今開いているゲームの中だけに残り、クリア、再読み込み、ステージ切り替えでは引き継ぎません。

途中の位置、適用したルール、読んだ手掛かり、仕掛けの状態は自動で保存します。同じブラウザで再び開いたら「続きから」で再開できます。最初から試す場合は「このステージを最初から」かRキーを使います。過去のクリア記録は消えません。

以前の練習ステージのクリア記録は引き継ぎます。謎解き編は初めて開いたときは最初の面から始まり、その後に保存した状態から再開できます。旧版でプレイしていた途中の状態を、謎解き編へ持ち込むことはありません。

保存は利用中のブラウザだけに残ります。別の端末へは共有されず、サイトデータを消すと記録も消えます。保存できない環境でも遊べます。壊れた保存や今のステージに合わないデータは使わず、新しく始めます。

## 任意のローカルAI連携

ローカルAIモードでは、文章から対象と動作の候補を作れます。例えば「石を大きくして浮かせたい」と入力すると、「石＋成長＋浮遊」のような候補を表示します。内容を確認してから適用するため、入力しただけでは世界は変わりません。

使えるのは、ゲームに用意された対象と動作です。未対応の動作や解釈できない文章は、その理由を表示します。実際の効果と操作方法はゲーム側の定義で決まり、AIが新しい処理を書いて実行することはありません。「ルールの名前をAIで考える」も任意で使えます。生成を待っている間も、通常のルール操作を続けられます。

### 準備と起動

1. [Python 3](https://www.python.org/downloads/)と[Ollama](https://ollama.com/)を準備し、Ollamaを起動します。Pythonの追加パッケージは使いません。
2. 利用するモデルを取得します。モデル本体は同梱していません。既にモデルがある場合はそれを選べます。

   ```sh
   ollama pull qwen3.5:4b
   ```

3. ZIPを解凍した作品フォルダでローカルサーバーを起動します。

   ```sh
   # macOS / Linux
   python3 server.py --port 8765
   # Windows
   py -3 server.py --port 8765
   ```

4. 自動で開いたブラウザ、または `http://127.0.0.1:8765/` を使います。
5. ローカルAIの「接続確認」を押し、導入済みのモデルを選びます。このPC内で動くモデルが対象で、クラウドモデルは表示しません。
6. 文章を入力し、「文章から候補を作る」を押します。
7. 対象と動作を確かめ、「この候補を適用」を押します。ゲーム側でもそのステージの条件を確認してから反映します。

生成を待つ間もゲームは操作できます。最初の生成ではモデルの読み込みに時間がかかることがあります。中止した直後に「処理中」と表示された場合は、少し待ってから再試行してください。

短い文章で、変えたい物体と性質を一つずつ伝えると試しやすくなります。「木を光らせて浮かせたい」「石を小さくしたい」などから始めてみてください。画面で未解放になっている動作は、AIの候補に含まれていてもその場では適用できません。

起動時に優先するモデルは、環境変数 `WORLD_DEFINITION_MODEL` でも設定できます。終了はターミナルでCtrl＋Cです。サーバーは同じコンピューターからだけ接続できる設定です。Pages版はAIの準備なしで全ステージを遊べます。

実際のOllamaモデルによる生成と、各OSでの実機動作は未検証です。APIの確認には模擬応答を使っています。利用するモデルやPCによって生成時間や文章の解釈が異なるため、候補を確認してから適用してください。

開発時の確認コマンドです。ローカルAIのテストは応答を模擬するため、モデルの導入なしで実行できます。

```sh
node tests/engine.test.js
node tests/mystery.test.js
node tests/app-input.test.js
node tests/progress.test.js
node tests/session.test.js
python3 -m unittest discover -s tests -p 'test_*.py'
```

ゲーム進行のテストは、謎解き編と練習ステージを最初からゴールまで進め、手掛かりと装置の関係、必要な操作の順序が成立するか確認します。定義をまとめて適用するだけで通過できないことや、解除後にも足場と帰り道が残ることを調べます。受信盤の条件、足場の保持、炎に触れた後の安全な岸への復帰も扱います。入力のテストはキーボード、画面ボタン、ダイアログ、リセット時の応答を扱います。表示の分かりやすさは実際のブラウザでも確認してください。実Ollamaによる生成とC++参照版のビルドは未確認です。

## 公開用ファイルの作成

リポジトリのルートで `python3 scripts/build_public_site.py` を実行すると、`_site/world-definition/` に公開用ファイルと配布ZIPが作られます。ZIPを解凍すると `v1.3.0/` になり、`index.html` を開いて遊べます。ソースはこの `projects/world-definition/` で管理します。

GitHub Pagesの初回設定は **Settings → Pages → Build and deployment → Source → GitHub Actions** です。その後はmainへの更新時に確認と配信を行います。Actionsの **Check and publish public works → Run workflow** からも再実行できます。
