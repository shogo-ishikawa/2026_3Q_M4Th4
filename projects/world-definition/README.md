# WORLD DEFINITION

**世界のルールを変えて、進める道を作るパズルゲームです。** 水を凍らせる、石を浮かせる、木の光を運ぶ。物体と動作を組み合わせ、基本5面と応用4面の全9ステージに挑みます。公開版のバージョンは **v1.2.1** です。

2026年度「計算科学基礎」の学生制作をもとにしています。C++・raylibの試作とJavaScript・Canvas版にあった「世界に働きかけて道を作る」という発想を引き継ぎました。公開版では定義による形・動き・光の変化を見やすくし、物体を運んで仕掛けを解くステージを追加しています。v1.2.1では基本5面を残し、縮小・回転を使う応用面、1手戻す操作、途中再開、文章からルールを提案する任意のローカルAI連携を加えました。

## すぐに遊ぶ

GitHub Pagesの作品ページ、またはダウンロードしたフォルダの **`index.html`** をブラウザで開きます。標準モードにはインストール、ログイン、APIキー、AIモデルの準備は必要ありません。ダウンロード後はオフラインでも遊べます。

1. 最初の説明を読み、遊び始めます。途中の保存があれば「続きから」で再開できます。
2. WASDまたは矢印キーで移動します。スマートフォンでは画面の方向ボタンを使います。
3. 研究室で物体と動作を選び、「ルールを適用」を押します。選択しただけでは世界は変わりません。
4. 変化を確かめながら青い結晶を拾い、ゲートを開いてゴールへ進みます。
5. クリアすると次のステージが解放されます。ステージ選択から解放済みの場所へ戻ることもできます。

詳しい手順と段階的なヒントは **[遊び方ガイド](guide.html)** にまとめています。ステージ別の攻略例は折り畳みを開いたときだけ表示します。

## 操作

| キー・ボタン | 動作 |
| --- | --- |
| WASD / 矢印 | プレイヤーの移動 |
| E＋移動 | 近くにある浮遊中の石・木を運ぶ |
| E長押し | 「炎＋加熱」を適用した後、ゲートの近くで立ち止まって加熱する |
| L | ルール研究室にフォーカスを移す |
| H | 操作説明を開く |
| J / 攻略ヒント | 現在の状況に合った攻略ヒントを開閉する |
| Z / 1手戻す | 直前の定義・運搬・物体の配置復旧を取り消す |
| R | 確認してから現在のステージをやり直す |
| Tab / Shift＋Tab | ボタンなどの選択を順に移す |
| Escape | 開いている説明を閉じる |
| ステージ選択 | 解放済みのステージを選んで遊ぶ |

画面の「操作」ボタンはEキーと同じ働きです。浮遊物体を運ぶときは方向ボタンと同時に押してください。複数の浮遊物体が近くにある場合は、研究室で選んだ石・木を優先します。選んだ物体が近くにない場合は、近い浮遊物体を運びます。

## 試して、1手戻す

定義や物体の運び方を変えてうまくいかなかったときは、**「1手戻す」またはZキー**を使います。直前の定義、ひと続きの運搬、物体の配置復旧を、その前の状態へ戻せます。移動キーを少し押すたびに1手を使う仕組みではありません。位置や途中の仕掛けもその時点へ戻るので、別の方法を試してみましょう。

戻せる履歴は今開いているゲームの中だけに残ります。クリア後、再読み込み後、ステージの切り替え後には引き継ぎません。ステージ全体を最初から遊ぶ場合は、やり直しボタンを使います。

## 困ったら攻略ヒントを開く

ゲーム画面の下にある **「攻略ヒント J」**、またはJキーで開閉できます。まず考え方を読み、必要に応じて「もっと具体的に」「答えの手順を見る」で詳しくします。前の段階にも戻れます。川を渡る、受信盤を点灯させる、ゲートを開くなど、進行に合わせてヒントが切り替わります。

「次に向かう場所を表示」にチェックすると、ゲーム画面に目印が出ます。近くの物体やゲートで使えるE操作は、画面の案内も確認してください。操作方法だけを読みたい場合はHキー、ステージ全体の攻略例は[遊び方ガイド](guide.html#stages)を使えます。

川の手前で配置に困ったときは、ヒント内の「運んだ物体の配置だけやり直す」を開き、石・木の配置を戻せます。定義と結晶、記録型の盤の点灯は残ります。同時維持の盤は配置に応じて変わります。橋が消えて先へ進めなくなるのを防ぐため、川の上や向こう岸からは使えません。

## 定義すると、何が変わるか

動作は物体ごとに最大3つまで組み合わせられます。対象に適用中の効果はバッジでも確認できます。

| 動作 | 見える変化・できること |
| --- | --- |
| 凍結 | 水面が氷になり、川を歩けます。炎に使うと消火されて安全に近づけます。 |
| 固体化 | 水面が石張りの通路へ変わります。 |
| 浮遊 | 石・木が地面から浮き、影と浮遊の表示が現れます。E＋移動で運び、川では足場として使えます。炎は上へ浮きます。 |
| 成長 | 石・木や炎が大きくなります。足場の幅と長さも広がるため、広い川で役立ちます。 |
| 縮小 | 石・木が小さくなり、狭い搬入口を通せます。足場も小さくなるので、渡る前に大きさを確かめます。 |
| 回転 | 石・木の足場を横向きにします。回転を外して適用し直すと縦向きへ戻ります。水路の向きに合わせて橋を架け替えます。 |
| 発光 | 対象が光源になります。光の紋章へ物体を運び、発光させる仕掛けもあります。 |
| 脈動 | 光が周期的に変化し、波紋が広がります。共鳴盤へ光と脈動を届けると作動します。 |
| 移動 | 炎が左右に往復します。移動の軌跡も表示されます。 |
| 加熱 | 炎が熱を帯びます。ゲートの近くでEを長押しすると加熱が進み、ゲートが開きます。結晶取得後に使えます。 |

| 物体 | 基本の動作 |
| --- | --- |
| 水 | 凍結、固体化、発光、脈動 |
| 石・木 | 浮遊、成長、縮小、回転、発光、脈動 |
| 炎 | 浮遊、移動、成長、発光、凍結、脈動、加熱 |

ステージによって使える動作に制限があります。基本ステージ2〜5では水の凍結と固体化が封印されるため、石や木を使います。応用面では盤に書かれた条件と、研究室で選べる動作を確かめてください。成長と縮小は同時には使えません。

ルールは物体ごとに残ります。水のルールを作った後で炎のルールを変えても、水のルールは残ります。同じ物体への再適用は置き換えです。川の途中で足場を失う変更は受け付けないため、いったん岸へ戻ってから変更してください。

## 基本5面と応用4面

| ステージ | 主な仕掛け |
| --- | --- |
| 1：封印されたゴール | 水を変える方法と浮遊物体を橋にする方法を試せます。結晶で加熱を解放する基本のステージです。 |
| 2：石の渡し場 | 水の定義が封印された川を、石や木の足場で渡ります。 |
| 3：光を運ぶ庭 | 木を光の紋章へ運び、発光させて封印を解きます。 |
| 4：脈動の回廊 | 石を共鳴盤へ運び、発光と脈動を組み合わせて作動させます。 |
| 5：最後の定義 | 広い川と2つの受信盤が登場します。石の成長と木の発光・脈動を使い分けます。 |
| 6：小さな入口、大きな足場 | 石を縮小して細い搬入口へ通し、その先で成長させて橋にします。 |
| 7：向きを変える橋 | 回転で横向きの足場を作り、縦に流れる水路を渡ります。 |
| 8：二つの灯を同時に | 石と木を別々の維持盤へ置き、両方を同時に点灯させます。 |
| 9：材質とリズム | 氷と石畳の記録盤を踏み、石の脈動で共鳴盤を充電します。 |

基本面の受信盤は、指定された物体を近くへ運び、必要な動作を約1秒間届けると点灯します。一度点灯した盤は、その後も点灯したままです。基本面では結晶と必要な盤をそろえ、炎に加熱を適用してゲートを開きます。応用面6〜9の門は、結晶と必要な盤がそろうと自動で開きます。炎の加熱は不要です。8の維持盤は物体を離すと消灯しますが、一度開いた門は閉じません。9のリズムの共鳴盤は明るい位相の間だけ充電するため、約4秒を目安にその場で待ちます。

応用面の目標定義回数は追加の挑戦です。回数を超えてもクリアできるので、最初は自由に試してください。

各ステージには金の欠片が2個あります。収集は追加の目標で、クリアの必須条件ではありません。まずゴールを目指し、慣れたら欠片を探したり少ない定義回数で解いたりしてみてください。

## 途中再開とクリア記録

プレイヤーと物体の位置、適用したルール、結晶・受信盤などの途中の状態は自動で保存します。同じブラウザで再び開いたときは、最初の画面の「続きから」で再開できます。「このステージを最初から」を選ぶと、そのステージを新しく始めます。

ステージの解放状況とクリア記録も保存します。記録には定義回数、集めた欠片、クリア時間が含まれます。基本5面の解放状況は、以前の版から引き継ぎます。

炎に触れたときは、最後に立っていた安全な岸へ戻ります。そこが物体で塞がっている場合は、近くの安全な場所へ戻ります。ルール、回収済みの結晶や欠片は残ります。応用面の「同時維持」の盤は、物体が条件を満たす位置にあるかを改めて調べます。

保存は利用中のブラウザだけに残ります。別の端末やブラウザには共有されず、サイトデータを消すと記録も消えます。保存できない環境でも遊べます。壊れた保存や今のステージに合わないデータは使わず、新しく始めます。

## 任意のローカルAI連携

ローカルAIモードでは、文章から対象と動作の候補を作れます。例えば「石を大きくして浮かせたい」と入力すると、「石＋成長＋浮遊」のような候補を表示します。内容を確認してから適用するため、入力しただけでは世界は変わりません。

使えるのは、ゲームに用意された対象と動作です。未対応の動作や解釈できない文章は、その理由を表示します。実際の効果と操作方法はゲーム側の定義で決まり、AIが新しい処理を書いて実行することはありません。「ルールの名前をAIで考える」も任意で使えます。生成を待っている間も、通常のルール操作を続けられます。

### 準備と起動

1. [Python 3](https://www.python.org/downloads/)と[Ollama](https://ollama.com/)を準備し、Ollamaを起動します。Pythonの追加パッケージは使いません。
2. 利用するモデルを取得します。モデル本体は同梱していません。既にモデルがある場合はそれを選べます。

   ```sh
   ollama pull qwen3.5:4b
   ```

3. ZIPを解凍した作品フォルダでローカルサーバーを起動します。

   ```sh
   # macOS / Linux
   python3 server.py --port 8765
   # Windows
   py -3 server.py --port 8765
   ```

4. 自動で開いたブラウザ、または `http://127.0.0.1:8765/` を使います。
5. ローカルAIの「接続確認」を押し、導入済みのモデルを選びます。このPC内で動くモデルが対象で、クラウドモデルは表示しません。
6. 文章を入力し、「文章から候補を作る」を押します。
7. 対象と動作を確かめ、「この候補を適用」を押します。ゲーム側でもそのステージの条件を確認してから反映します。

生成を待つ間もゲームは操作できます。最初の生成ではモデルの読み込みに時間がかかることがあります。中止した直後に「処理中」と表示された場合は、少し待ってから再試行してください。

短い文章で、変えたい物体と性質を一つずつ伝えると試しやすくなります。「木を光らせて浮かせたい」「石を小さくしたい」などから始めてみてください。画面で未解放になっている動作は、AIの候補に含まれていてもその場では適用できません。

起動時に優先するモデルは、環境変数 `WORLD_DEFINITION_MODEL` でも設定できます。終了はターミナルでCtrl＋Cです。サーバーは同じコンピューターからだけ接続できる設定です。Pages版はAIの準備なしで全ステージを遊べます。

実際のOllamaモデルによる生成と、各OSでの実機動作は未検証です。APIの確認には模擬応答を使っています。利用するモデルやPCによって生成時間や文章の解釈が異なるため、候補を確認してから適用してください。

## コードを読む・変えてみる

| ファイル | 内容 |
| --- | --- |
| `index.html` / `style.css` | 画面の構造と見た目 |
| `engine.js` | ステージのデータ、世界の状態、ルール、移動と当たり判定 |
| `progress.js` | この端末の解放状況とベスト記録 |
| `session.js` | 1手戻す履歴と途中の状態の保存・読み込み |
| `renderer.js` | 物体や効果、ステージの描画 |
| `app.js` | 入力、画面更新、ステージの選択と進行 |
| `server.py` | 任意のローカルAI連携 |
| `tests/` | ステージの攻略、入力、ローカルサーバーなどの確認 |
| [docs/design.md](docs/design.md) | 処理の流れと変更して試す課題 |
| [native-reference/](native-reference/) | 元のC++版の参照用ソースと素材の利用条件 |

開発時の確認コマンドです。ローカルAIのテストは応答を模擬するため、モデルの導入なしで実行できます。

```sh
node tests/engine.test.js
node tests/app-input.test.js
node tests/progress.test.js
node tests/session.test.js
python3 -m unittest discover -s tests -p 'test_*.py'
```

ゲーム進行のテストは基本面と応用面を最初からゴールまで進め、必要な定義や仕掛けが実際に成立するか確認します。受信盤の条件、足場の保持、炎に触れた後の安全な岸への復帰も扱います。入力のテストはキーボード、画面ボタン、ダイアログ、リセット時の応答を扱います。表示の分かりやすさは実際のブラウザでも確認してください。実Ollamaによる生成とC++参照版のビルドは未確認です。

## 公開用ファイルの作成

リポジトリのルートで `python3 scripts/build_public_site.py` を実行すると、`_site/world-definition/` に公開用ファイルと配布ZIPが作られます。ZIPを解凍すると `v1.2.1/` になり、`index.html` を開いて遊べます。ソースはこの `projects/world-definition/` で管理します。

GitHub Pagesの初回設定は **Settings → Pages → Build and deployment → Source → GitHub Actions** です。その後はmainへの更新時に確認と配信を行います。Actionsの **Check and publish public works → Run workflow** からも再実行できます。
