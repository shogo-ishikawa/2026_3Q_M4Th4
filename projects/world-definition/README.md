# WORLD DEFINITION

**世界のルールを変えて、進める道を作るパズルゲームです。** 水を凍らせる、石を浮かせて足場にするなど、物体と動作を組み合わせてゴールを目指します。公開版 v1.0.0 は、川・結晶・金属ゲートのある1ステージです。

2026年度「計算科学基礎」の学生制作をもとにしています。C++・raylibでの試作と、それを移したJavaScript・Canvas版にあった「世界に働きかけて道を作る」という発想を引き継ぎ、公開版では表示、操作、当たり判定、ルールの保持、遊び方の案内を整えました。

## すぐに遊ぶ

GitHub Pagesの作品ページ、またはダウンロードしたフォルダの **`index.html`** をブラウザで開きます。標準モードには、インストール、ログイン、APIキー、AIモデルは必要ありません。ダウンロード後はオフラインでも遊べます。

1. 最初の説明を読み、「遊び始める」を押します。
2. WASDまたは矢印キーで移動します。スマートフォンでは画面の方向ボタンを使います。
3. ルール研究室で物体と動作を選び、ルールを適用します。
4. 地形や物体の変化を確かめながら、結晶とゴールを目指します。

詳しい手順、操作一覧、段階的なヒントは **[遊び方ガイド](guide.html)** にまとめています。攻略例はガイドの折り畳みを開いたときだけ表示します。

## 操作

| キー・ボタン | 動作 |
| --- | --- |
| WASD / 矢印 | プレイヤーの移動 |
| E＋移動 | 近くにある浮遊中の石・木を運ぶ |
| E長押し | 「炎＋加熱」を適用した後、ゲートの近くで加熱する |
| L | ルール研究室にフォーカスを移す |
| H | 操作説明を開く |
| R | 確認してからステージを最初からやり直す |
| Tab / Shift＋Tab | ボタンなどの選択を順に移す |
| Escape | 開いている説明を閉じる |

## ルールの仕組み

動作は最大3つまで組み合わせられます。選べる動作は物体ごとに異なります。水のルールを適用した後で炎のルールを作っても、水のルールは残ります。同じ物体への再適用では、その物体の動作を置き換えます。川の途中で足場を失うような変更は受け付けません。

| 物体 | 選べる動作 |
| --- | --- |
| 水 | 凍結、固体化、発光、脈動 |
| 石・木 | 浮遊、成長、発光、脈動 |
| 炎 | 浮遊、移動、成長、発光、凍結、脈動、加熱 |

「加熱」は結晶を取ると使えます。「発光」「脈動」は見た目の変化を楽しむ動作です。対応していない組合せを、働く機能として表示しない構成にしています。

## 任意のローカルAI連携

標準モードでは、名前と説明も選んだ動作に応じてブラウザ内で組み立てます。ローカルAIを使う場合は、Ollamaが**ルールの名前と説明**を補助します。実際の効果はゲーム側で定めた処理です。自由な文章から新しいゲーム処理を生成する機能はありません。

1. [Ollama](https://ollama.com/)を導入し、起動します。
2. ターミナルでモデルを取得します。モデル本体は同梱していません。

   ```sh
   ollama pull qwen3.5:4b
   ```

3. この作品フォルダでローカルサーバーを起動します。

   ```sh
   # macOS / Linux
   python3 server.py --port 8765
   # Windows
   py -3 server.py --port 8765
   ```

4. `http://127.0.0.1:8765/` を開き、ローカルAIの選択肢を有効にします。

別の導入済みモデルを使う場合は、起動前に環境変数 `WORLD_DEFINITION_MODEL` を設定してください。終了はターミナルで Ctrl＋C です。サーバーは同じコンピューターからだけ接続できる設定です。GitHub PagesではローカルAI連携を使いません。実モデルによる生成と各OSでの実機動作は未検証です。

## コードを読む・変えてみる

| ファイル | 内容 |
| --- | --- |
| `index.html` / `style.css` | 画面の構造と見た目 |
| `engine.js` | 世界の状態、ルールの適用、移動と当たり判定 |
| `app.js` | 入力、画面更新、描画 |
| `server.py` | 任意のローカルAI連携 |
| `tests/` | ゲーム進行やローカルサーバーの確認 |
| [docs/design.md](docs/design.md) | 処理の流れと変更して試す課題 |
| [native-reference/](native-reference/) | 元のC++版の参照用ソースと素材の利用条件 |

ゲーム処理と描画を分けているため、見た目を変更しながら、移動・判定の仕組みも確認できます。複数ステージや自由文章によるルール作成は、今後の発展案です。

開発時の確認コマンドは次のとおりです。ローカルAIのテストは応答を模擬し、モデルの導入なしで行います。

```sh
node tests/engine.test.js
node tests/app-input.test.js
python3 -m unittest discover -s tests -p 'test_*.py'
```

公開用の標準ゲームはHTML・CSS・JavaScriptだけで動きます。C++版のビルド環境や素材は読み込みません。

## 公開用ファイルの作成

リポジトリのルートで `python3 scripts/build_public_site.py` を実行すると、`_site/world-definition/` に公開用の5ファイルと配布ZIPが作られます。ZIPは解凍すると `v1.0.0/` になり、`index.html` を開いて遊べます。ソースはこの `projects/world-definition/` で管理し、公開先にはゲームとガイドだけを配置します。

GitHub Pagesの初回設定はリポジトリの **Settings → Pages → Build and deployment → Source → GitHub Actions** です。その後、mainへの更新時に公開用ワークフローが確認と配信を行います。初回設定後はActionsから **Check and publish public works → Run workflow** でも再実行できます。

確認環境：Node.js 24.22.1、Python 3.12.14。ゲーム進行の25チェック、入力制御の10チェック、ローカルサーバーの21テストを実行しました。ブラウザでは初回案内、選択と適用、操作説明、リセット、ガイドを確認しています。実OllamaとC++参照版のビルドは未確認です。
