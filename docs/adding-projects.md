# 新しい作品の追加手順

## 1．作品の名前とフォルダを決める

`projects/<project-slug>/` に作品を追加します。フォルダ名には内容が分かる短い英小文字とハイフンを使い、学生の氏名や学籍番号を使わないでください。例は `guitar-chord-lab` です。

新しい作品を追加する前に、ルートの [AGENTS.md](../AGENTS.md) を確認します。

## 2．作品の中に必要なファイルを置く

| 配置先の例 | 内容 |
| --- | --- |
| `README.md` | 作品の目的、実装状況、実行手順、入力と出力、制約 |
| `pyproject.toml` または `requirements.txt` | その作品の依存ライブラリと導入方法 |
| `src/` | Notebookからも利用するPythonコード |
| `notebooks/` | Colab等で使う教材・実行例 |
| `tests/` | 主要な処理を確認するテスト |
| `configs/` | 再現可能な設定例 |
| `data/README.md` | データの出典、取得・生成方法、注釈の意味 |
| `AGENTS.md`・`CLAUDE.md` | 作品固有の開発ルールが必要な場合の指示 |

必要なものから作成し、実際に利用するファイルを追加してください。動作することを確認してから、インストールコマンドとNotebookへのリンクを掲載します。

## 3．作品だけで実行できるようにする

他の作品の依存定義を変更せず、その作品の環境を用意します。Colabではリポジトリを取得した後、対象作品のフォルダを指定して導入・実行する手順を説明してください。Notebook内の相対パスが、どの作業ディレクトリを基準にするかも明記します。

音源や大きなデータ、モデル重みは原則としてコミットせず、取得方法と保存先を説明します。生成した出力も、ソースとは別の場所に保存します。小さな設定例や注釈CSVは、公開してよいことを確認したうえで追加できます。

## 4．変更を確認して共有する

作品名と変更目的が分かるブランチを使います。例えば `guitar-chord-lab/add-chroma-analysis` とし、プルリクエストには変更による動作と検証結果を書きます。AIに依頼する際も、編集する作品のフォルダを明示してください。

公開する差分に個人情報、認証情報、内部連絡、不要な音源や生成ファイルが含まれていないことを確認します。確認できていない機能は、その状態をREADMEと報告に記載します。

最後に、ルートのREADMEの作品一覧へ説明とリンクを追加します。

## 5．版と配布物を管理する

リポジトリ内に版ごとのソースを複製せず、Gitの履歴で管理します。版のタグには `guitar-chord-lab-v0.1.0` のように作品名を含めると区別しやすくなります。

配布用ZIPが必要な場合は、その作品だけの必要ファイルを集め、解凍後の最上位フォルダを `v0.1.0/` のようにします。仮想環境、モデル重み、キャッシュ、大きな入力音源、生成結果を配布ZIPへ入れないようにします。
